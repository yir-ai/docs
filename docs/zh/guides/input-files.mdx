---
title: 输入文件
description: 用 Files API 上传参考图片、视频和音频，并在生成请求中引用。
---

所有图片、视频和音频参考都必须先通过 Files API 上传；生成请求不接受外部参考 URL。生成接口不接受 Base64、Data URL 或 multipart 请求体。

## 限制

| 项目 | 限制 |
| --- | --- |
| 每次创建的文件数 | 1–20 |
| 单个文件大小 | 最大 2 GiB |
| 媒体类型 | `image/jpeg`、`image/png`、`image/webp`、`video/mp4`、`video/webm`、`audio/mpeg`、`audio/wav` |

文件是临时的，在 `expires_at` 到期；查询状态不会延长有效期。

## 上传流程

<Steps>
  <Step title="创建上传计划">
    把文件元数据发送到 `POST /v1/files`。携带 `Idempotency-Key` Header，重试时会返回同一份计划。
  </Step>
  <Step title="上传内容">
    按 `part_number` 顺序，把对应字节段 `PUT` 到 `upload.parts` 中每个分片的 `url`。不要向这些地址发送 Yir API Key。
  </Step>
  <Step title="完成文件">
    用空 JSON 请求体调用 `POST /v1/files/{id}/complete`，文件进入 `processing`。轮询 `GET /v1/files/{id}`，等到 `ready` 后再引用；遇到 `failed` 或 `expired` 时停止等待。
  </Step>
  <Step title="引用文件">
    在报价或生成请求的 `input.references` 中使用 `{ "role": "...", "file_id": "file_..." }`。
  </Step>
</Steps>

### 1. 创建上传计划

```bash
curl https://gateway.yir.ai/v1/files \
  --header "Authorization: Bearer $YIR_API_KEY" \
  --header "Content-Type: application/json" \
  --header "Idempotency-Key: upload-first-frame-001" \
  --data '{ "files": [{ "name": "first-frame.png", "media_type": "image/png", "size": 482133 }] }'
```

`size` 必须是准确的字节数。响应按相同顺序为每个条目返回一个 File：

```json
{
  "files": [{
    "id": "file_11111111-1111-4111-8111-111111111111",
    "object": "file",
    "status": "pending_upload",
    "name": "first-frame.png",
    "media_type": "image/png",
    "size": 482133,
    "upload": {
      "type": "multipart",
      "expires_at": 1790000900,
      "parts": [{ "part_number": 1, "size": 482133, "url": "https://..." }]
    }
  }]
}
```

批量中只要有一个条目无效，整批请求都会被拒绝。

### 2. 上传每个分片

```bash
curl --request PUT --upload-file first-frame.png "$PART_URL"
```

多分片计划需按列出的 `size` 把文件切成连续字节段，并在 `upload.expires_at` 之前完成上传。

### 3. 完成

```bash
curl --request POST https://gateway.yir.ai/v1/files/$FILE_ID/complete \
  --header "Authorization: Bearer $YIR_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{}'
```

只有 `ready` 状态的文件能用于请求。引用的文件不存在、未完成或已过期时，各接口的表现不同：

| 接口 | 结果 |
| --- | --- |
| 报价 | 返回 `200`，报价中 `supply.available: false`、`issues: ["no_matching_supply"]`。文件会在报价有效期内过期时同样如此。 |
| 生成 | `400 YIR_INVALID_REQUEST`，不创建 Job。 |
| `GET /v1/files/{id}` | 返回 `200` 和文件快照，请读取其 `status`（`pending_upload`、`processing`、`ready`、`expired` 或 `failed`）。文件不存在时返回 `404 YIR_FILE_NOT_FOUND`。 |
| `POST /v1/files/{id}/complete`、`GET /v1/files/{id}/content` | `404 YIR_FILE_NOT_FOUND`、`409 YIR_FILE_NOT_READY` 或 `410 YIR_FILE_EXPIRED`。 |

## 读取文件

`GET /v1/files/{id}` 返回当前状态。`GET /v1/files/{id}/content` 以 `307` 重定向到短期签名地址。API Key 只发送给 Gateway，不要发送给重定向目标。File 上的 `url` 字段是用于这种认证读取的路径，不能作为生成请求中的参考地址。

## 使用 SDK

SDK 封装了全部三个步骤。Go 中 `CreateAndUploadFile` 是 client 方法；TypeScript 中 `createAndUploadFile` 是从 `@yir-ai/sdk/server` 导出的函数，第一个参数传入 client：

```ts
import { readFile } from "node:fs/promises";
import { createAndUploadFile, createNodeYirClient } from "@yir-ai/sdk/server";

const client = createNodeYirClient();
const bytes = await readFile("reference.png");
const file = await createAndUploadFile(
  client,
  { name: "reference.png", media_type: "image/png", size: bytes.byteLength },
  new Blob([bytes]),
  "upload-reference-001",
);
console.log(file.id, file.status); // "ready": reference it by file.id
```

请持久化该幂等键，崩溃后用同一个键恢复。见 [SDK](/zh/docs/guides/clients)。

自 TypeScript SDK 0.4.0 和 Go SDK 0.5.0 起，上传辅助函数会等待分析，默认超时五分钟。可用 `waitForFileReady` / `WaitForFileReady` 继续等待；本地超时不会取消服务端分析。读取 ready 文件时，`getFileContentURL` / `GetFileContentURL`（TypeScript 0.5.0 / Go 0.6.0）返回其签名 URL，不会把 API Key 发给存储端。
