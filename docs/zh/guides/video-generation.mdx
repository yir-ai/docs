视频 Job 提交到 `POST /v1/videos/generations`。视频遵循与图片相同的[生命周期](/zh/docs/concepts/task-lifecycle)、[计费](/zh/docs/concepts/billing)和[路由](/zh/docs/concepts/routing)规则，但通常需要数分钟而不是数秒，因此 [Webhook](/zh/docs/production/webhooks) 往往比轮询更合适。

## 输入方式

| `input.type` | 用途 | 参考角色 |
| --- | --- | --- |
| `text` | 文生视频 | 无 |
| `image` | 从首帧开始生成，可选经过有序关键帧并指定尾帧 | `first_frame`、`keyframe`、`last_frame` |
| `reference` | 用多种素材引导视频 | `reference_image`、`reference_video`、`reference_audio` |

每个图片、视频或音频参考用 `role` 加上 `file_id`（先通过 [Files API](/zh/docs/guides/input-files) 上传并等到 `ready`）或由 Yir 在提交时下载的公开 HTTPS `url` 引用。URL 限制见[输入文件](/zh/docs/guides/input-files#公开-url)。

模型支持哪些输入方式、角色和数量由其合同决定。例如 Seedance 2.0 在 `image` 模式下接受一个 `first_frame` 和可选的 `last_frame`；在 `reference` 模式下最多接受 9 张图片、3 段视频和 3 段音频（至少一张图片或一段视频）。Kling 4.0 在 `image` 模式下还接受最多 8 个 `keyframe`，按在 `references` 中出现的先后顺序排列。

## 幻术动作迁移与对象替换

调用 `POST /v1/videos/generations`，将 `input.type` 设为 `"reference"`。Yir 根据 `model` 选择动作迁移、标准对象替换或 Lite 对象替换。

| 模式 | Yir 模型 ID | 参考图的用途 | 源 MP4 时长 | 输出分辨率 |
| --- | --- | --- | --- | --- |
| 动作迁移 | [`nanoapi/genjutsu-1.0`](/zh/docs/models/nanoapi/genjutsu-1-0) | 提供目标人物的照片，让其复现源视频里的动作 | 1–30 秒 | `480p`、`720p`、`1080p` |
| 对象替换 | [`higgsfield/genjutsu-1.0-object-swap`](/zh/docs/models/higgsfield/genjutsu-1-0-object-swap) | 提供替换物的图片，用它替换源视频中指定的对象 | 4–30 秒 | `480p`、`720p`、`1080p` |
| 对象替换（Lite） | [`higgsfield/genjutsu-lite-1.0`](/zh/docs/models/higgsfield/genjutsu-lite-1-0) | 提供替换物的图片，用它替换源视频中指定的对象 | 4–30 秒 | `720p`、`1080p` |

三种模式都需要恰好一段 `reference_video` 和 1–10 张 `reference_image`，默认分辨率为 `720p`。Standard API 的提示词可省略，最多 5000 个字符。若所用 SDK 要求提示词，可参考下面的写法。需要有金额的报价时，先用 [Files API](/zh/docs/guides/input-files) 上传源 MP4，再传已就绪的 `file_id`。

<Tabs>
<Tab title="动作迁移">

```json
{
  "model": "nanoapi/genjutsu-1.0",
  "input": {
    "type": "reference",
    "prompt": "让参考照片里的人复现源视频中的舞蹈动作。",
    "references": [
      { "role": "reference_video", "file_id": "file_22222222-2222-4222-8222-222222222222" },
      { "role": "reference_image", "file_id": "file_66666666-6666-4666-8666-666666666666" }
    ]
  },
  "parameters": { "resolution": "720p" }
}
```

</Tab>
<Tab title="对象替换">

```json
{
  "model": "higgsfield/genjutsu-1.0-object-swap",
  "input": {
    "type": "reference",
    "prompt": "把 @video_1 里的红色马克杯换成 @image_1 里的蓝色马克杯。",
    "references": [
      { "role": "reference_video", "file_id": "file_22222222-2222-4222-8222-222222222222" },
      { "role": "reference_image", "file_id": "file_66666666-6666-4666-8666-666666666666" }
    ]
  },
  "parameters": { "resolution": "720p" }
}
```

</Tab>
</Tabs>

在对象替换的提示词里，`@video_1` 指源视频，`@image_1`、`@image_2` 等按图片在 `references` 中的顺序对应替换图。用 Lite 时把示例中的 `model` 换为 `higgsfield/genjutsu-lite-1.0`。请把示例文件 ID 换成你自己的已就绪文件。

## 常用参数

| 参数 | 说明 |
| --- | --- |
| `duration` | 输出时长（秒），需在模型范围内；支持的参考视频编辑可用 `"auto"`。Quote 和 Job 保留 `"auto"`；URL 报价可在供给可用时保持金额未知。见 [Seedance 2.5](/zh/docs/models/bytedance/seedance-2-5)。 |
| `task_type` | 仅 Seedance 2.5 的 `reference` 模式：`auto`（默认）、`reference`、`edit` 或 `extend`。见 [Seedance 2.5](/zh/docs/models/bytedance/seedance-2-5)。 |
| `resolution` | 例如 `480p`、`720p`、`1080p`。 |
| `aspect_ratio` | 例如 `16:9`、`9:16`、`1:1`，支持时可用 `adaptive`。 |
| `generate_audio` | 支持时随视频生成原生音频。 |
| `return_last_frame` | 仅 Seedance 2.0：额外返回最后一帧图片，需要支持该选项的渠道。 |
| `n` | 固定为 `1`。 |

模型的具体取值可通过 `GET /v1/models/{creator}/{model}?view=contract` 查询。

## 提交前先报价

视频价格取决于时长、分辨率、音频和参考素材，因此请先用 `POST /v1/videos/quotes` 对完整请求报价。包含已上传（`file_id`）视频或音频参考的报价会使用其实测时长。Yir 报价时不下载 `url` 引用，因此对 Seedance 2.0、2.0 Fast、2.0 Mini、2.5 与 MiniMax H3、H3 Max，可以在 `url` 参考视频或参考音频上加 `duration_seconds`：报价按你声明的时长计算输入媒体费用，并返回 `input_duration_source: "declared"`。不声明时，`url` 参考视频的报价没有完整价格。提交时忽略 `duration_seconds`，Job 按导入后的实测时长准入和扣费。检查 `supply.available`。报价是估价，最终费用以实际成本为准；需要封顶时，在提交中携带 `max_cost`。

Kling Motion Control（`reference_image` + `reference_video`）按参考视频实测时长计价，按整秒向下取整；请求里的 `duration` 不影响价格。上传参考视频并传入其 `file_id`，报价才有金额；参考视频是 URL 时报价没有金额，带 `max_cost` 的请求会被拒绝。见[报价与计费](/zh/docs/concepts/billing)。

## 结果

成功的视频 Job 在 `result.files` 中返回视频。请求 `return_last_frame` 时，尾帧作为额外的图片文件返回。如果只有这个额外文件未能交付，Job 仍然成功，并带有 `result.warnings: ["additional_results_unavailable"]`。
