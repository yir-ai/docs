上线前请逐项确认。每一节都链接到详细说明该规则的页面。

## 检查清单

- API Key 只保存在服务端，每个环境使用独立 Key。
- 每次提交都有已持久化的幂等键，重试同一请求时复用。
- 提交前后把请求、幂等键和 Job ID 一起保存。
- 轮询有上限、会退避，停止时只影响本地。
- 终态结果按 Job ID 只处理一次，无论来自轮询还是 Webhook。
- 基于原始字节校验 Webhook 签名，并对事件去重。
- 结果文件在过期前复制到自己的存储。
- 通过可选的 `max_cost`、低余额提醒和每个 Key 的月度上限控制支出。
- 错误处理按 `error.code` 与 `error.action` 分支。

## 幂等提交

每个生成请求都必须携带 `Idempotency-Key` Header（1–200 个字符），它让提交可以安全重试：

- 相同的键与相同的请求：返回原来的 Job，不会新建。
- 相同的键与不同的请求：以 `409 YIR_IDEMPOTENCY_CONFLICT` 拒绝。
- 缺少键或为空：在创建 Job 之前以 `400 YIR_INVALID_REQUEST` 拒绝。

为每个逻辑生成任务生成一个键（例如 `order-123-image-1`），并**在发送前与请求一起保存**。提交超时或进程崩溃后，用相同的键再次发送相同的请求。不要因为响应慢就换新键，第一次请求可能已经被接受。

请保持完整请求不变，包括 `max_cost`、`routing`、参考素材和 `webhook_url`。不要在已有键下重新报价并修改 `max_cost`。

## 保存哪些信息

每个生成任务一起保存：

| 字段 | 用途 |
| --- | --- |
| 自有请求 ID | 把 Job 关联到你的业务对象。 |
| 请求体与幂等键 | 用于恢复结果未知的提交。 |
| Yir Job ID | 查询状态、结果与取消的唯一句柄。 |
| 最近观察到的状态 | 重启后继续轮询。 |
| 终态是否已处理 | 防止重复扣费或重复发放积分。 |

不要把 API Key 与 Job 记录保存在一起。

## 等待结果

二选一或组合使用：

- **轮询：** 以退避节奏（5 秒、10 秒、20 秒）查询 `GET /v1/jobs/{id}/status`，进入终态后读取一次 `GET /v1/jobs/{id}`。
- **Webhook：** 设置 `webhook_url` 并处理终态 Job，见 [Webhook](/zh/docs/guides/webhooks)。

常见的稳健做法是以 Webhook 为主信号，并保留低频轮询兜底丢失的回调。无论哪种方式，终态 Job 都要**按 Job ID 只处理一次**。

## 恢复对照表

| 情况 | 处理方式 |
| --- | --- |
| 提交超时或连接中断 | 用相同的幂等键重发完全相同的请求。 |
| 状态查询超时 | 重试状态查询，Job 不受影响。 |
| 状态为 `queued`、`running` 或 `delivering` | 等待后再查。慢不等于失败。 |
| 本地等待到达截止时间 | 停止等待，保留 Job ID，稍后继续。不要重新提交。 |
| 状态为 `succeeded` | 读取完整 Job，复制 `result.files`，记录 `billing.total_charged_by_yir`。 |
| 状态为 `failed` | 读取完整 Job，处理 `error.code`，不收费。 |
| 状态为 `cancelled` | 读取完整 Job，`error` 可能为 `null`，不收费。 |
| 完整 Job 查询失败 | 重试该查询，不要仅凭状态摘要结算。 |
| `401`、`403` 或 `404` | 修正 Key、上限或 Job ID，不要盲目重试。 |
| `429 YIR_RATE_LIMITED` 或 `503` | 稍后退避重试。 |

所有错误码及建议处理方式见[错误码](/zh/docs/support/error-codes)。

## 控制费用

- 对请求报价查看估价。最终费用以实际成本为准；需要为每个 Job 设硬上限时，设置可选的 `max_cost`。见[报价与计费](/zh/docs/concepts/billing)。
- 在 Console 为每个 API Key 设置月度支出上限，并开启低余额邮件提醒。
- 如果更希望只尝试一次而不是自动恢复，可设置 `routing.fallback: false`。

## 安全测试

用只含一个渠道的 `routing.only` 定点测试，使用单独的、设置了较低月度上限的 API Key，并选择低成本参数。生成请求始终会创建真实 Job 并产生真实费用。

## 联系支持

请提供 Job ID、接口、大致 UTC 时间、HTTP 状态、`error.code` 以及错误响应中的 `request_id`。不要发送完整 API Key、提示词、源素材或签名密钥。
