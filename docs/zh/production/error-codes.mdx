无论来自 HTTP 请求还是出现在失败的 Job 上，错误都使用同一种结构：

```json
{
  "error": {
    "code": "YIR_INSUFFICIENT_BALANCE",
    "message": "The wallet balance is insufficient.",
    "retryable": false,
    "action": "add_funds"
  },
  "request_id": "example-request-id"
}
```

- `code` 是稳定的，请据此分支；不要解析可能变化的 `message`。
- `retryable` 表示稍后再试是否可能成功。
- `action` 建议下一步：`fix_request`、`modify_input`、`add_funds`、`retry_later` 或 `contact_support`。
- `request_id` 标识这次 HTTP 请求，联系支持时请提供。
- 字段级的 `YIR_INVALID_REQUEST` 错误带 `details`。每一项给出字段 `field`（如 `parameters.resolution`）、稳定原因码 `reason`（`unsupported`、`required`、`wrong_type`、`not_allowed`、`invalid`、`unknown_field`、`invalid_body` 或 `retired`），字段取值固定时还给出模型合同中的允许值 `allowed`。据此修正请求，不要解析 `message`。

Job 失败时，`GET /v1/jobs/{id}` 与 `GET /v1/jobs/{id}/status` 中都有相同的 `error` 对象（不含 `request_id`）。

## 请求错误

HTTP 调用立即返回。生成请求以这种方式被拒绝时，不会创建 Job，也不会收费。

| 错误码 | HTTP | 含义 | 处理方式 |
| --- | --- | --- | --- |
| `YIR_INVALID_REQUEST` | 400 | 请求体、参数或参考素材不符合 API 或模型合同，或生成请求缺少 `Idempotency-Key`。生成请求引用不存在、处理失败或已过期的输入文件，或参考 `url` 无法导入时，也返回此错误码（报价对处理失败或已过期的文件返回 `supply.available: false`）。URL 导入因远端超时、连接失败、HTTP 429 或 5xx 失败时 `retryable` 为 `true`。 | 修正请求，查看模型[合同](/zh/docs/models)。 |
| `YIR_INVALID_ROUTING_OVERRIDE` | 400 | `routing` 对象无效，例如 `only` 为空，或 `variants` 中的渠道不在 `only` 内。 | 修正 `routing`，见[路由](/zh/docs/concepts/routing)。 |
| `YIR_ROUTING_OVERRIDE_NOT_ALLOWED` | — | 合同中的保留错误码，目前不会返回。`routing` 无效时返回 `YIR_INVALID_ROUTING_OVERRIDE`。 | 如果对每个错误码分别处理，按 `YIR_INVALID_ROUTING_OVERRIDE` 处理即可。 |
| `YIR_UNAUTHORIZED` | 401 | Key 缺失、错误、已轮换、已吊销、已过期，或来源 IP 不被允许。 | 在 Console 检查 Key 及其设置，不要原样重试。 |
| `YIR_INSUFFICIENT_BALANCE` | 402 | 可用余额不足以覆盖首选渠道的估价，或余额为负。 | 充值后再提交。 |
| `YIR_SPEND_LIMIT_EXCEEDED` | 403 | 会超出该 Key 的月度支出上限。 | 提高上限，或等到下一个 UTC 自然月。 |
| `YIR_MODEL_NOT_FOUND` | 404 | 模型路径中的模型 ID 不存在。 | 使用 `GET /v1/models` 返回的规范 ID。 |
| `YIR_JOB_NOT_FOUND` | 404 | 该账户下没有此 Job，或已超过 90 天。 | 检查 Job ID 和 Key 所属账户。 |
| `YIR_FILE_NOT_FOUND` | 404 | Files 接口或报价：该账户下没有此输入文件。 | 检查文件 ID，或重新上传。 |
| `YIR_IDEMPOTENCY_CONFLICT` | 409 | 该幂等键已用于另一个不同的请求。 | 重发原始请求；若是新请求，使用新键。 |
| `YIR_FILE_NOT_READY` | 409 | 文件尚未 `ready`：上传未完成时调用 `/complete`、`/content`，或报价、生成请求引用了仍处于 `pending_upload`、`processing` 的文件（`retryable: true`）。`GET /v1/files/{id}` 则返回 `200` 并在 `status` 中体现。 | 完成上传并调用 `/complete`，等到 `ready` 后用同一个幂等键重试。 |
| `YIR_JOB_NOT_CANCELLABLE` | 409 | Job 已成功或已失败。 | 无需取消，读取 Job 即可。 |
| `YIR_FILE_EXPIRED` | 410 | 仅 Files 接口（`/complete`、`/content`）：输入文件已过期。`GET /v1/files/{id}` 则返回 `200` 且 `status` 为 `expired`。 | 重新上传。 |
| `YIR_BUDGET_EXCEEDED` | 422 | 请求的 `max_cost` 低于所有可用渠道的当前估价，消息给出最低估价。价格会变，之前能通过的上限现在可能失败。 | 重新报价；接受新价格就在新请求中调高 `max_cost`，否则换更便宜的模型或规格。 |
| `YIR_NO_EXECUTABLE_ROUTE` | 422 | 当前没有渠道能在约束内执行此请求。 | 稍后重试、放宽 `routing` 或调整参数；报价可查看 `supply`。 |
| `YIR_FIDELITY_EXCLUDED` | 422 | 该规格的所有渠道都低于请求的 `routing.fidelity`。 | 降低 `fidelity`，或换模型、换规格。见[规格真实性](/zh/docs/concepts/routing#规格真实性)。 |
| `YIR_RATE_LIMITED` | 429 | 该 API Key 超出每分钟请求上限（任意网关端点都可能返回），或账户进行中的 Job 过多。 | 按响应头 `Retry-After` 的秒数等待后重试；进行中的 Job 过多时等待其结束。 |
| `YIR_TEMPORARILY_UNAVAILABLE` | 503 | 临时的服务问题。 | 退避重试；提交请求请复用同一个幂等键。 |

## Job 错误

出现在状态为 `failed` 的 Job 上。失败的 Job 只按渠道实际计费的尝试收费（例如渠道已生成并计费的结果被判为 `YIR_CONTENT_REJECTED`，或渠道计费后才失败的尝试）；渠道没计费的尝试不收费，导致 `YIR_RESULT_DELIVERY_FAILED`、`YIR_OUTCOME_TIMEOUT` 或 `YIR_JOB_TIMEOUT` 的那次尝试永不收费。

| 错误码 | 含义 | 处理方式 |
| --- | --- | --- |
| `YIR_EXECUTION_FAILED` | 所有可用尝试均失败，或 Yir 在发起尝试前未能准备好输入文件（此时 `action` 为 `contact_support`）。 | 检查提示词和输入后提交新请求；持续出现请联系支持。 |
| `YIR_CONTENT_REJECTED` | Job 被内容安全检测拒绝：Yir 在提交前对参考图的检测、渠道对提示词、参考图或生成结果的审核，或 Yir 对无审核渠道图片结果的检测（见[内容安全](/zh/docs/concepts/task-lifecycle#内容安全)）。Yir 不会再切换到其他渠道。提交前被拦截，或渠道未对该尝试计费时（例如拒绝了提交）不收费；渠道已生成结果并计费时，按该上游实际费用 × 你的折扣收费，且不交付结果。Job 状态仍为 `failed`，Console 将其标为「内容拦截」，不计入成功率和失败率。 | 不可重试（`action: modify_input`），请让终端用户修改提示词或参考图后提交新请求。 |
| `YIR_NO_EXECUTABLE_ROUTE` | 准入后没有渠道能执行，或所有可用渠道均已用尽。 | 稍后重新提交，或放宽 `routing`。 |
| `YIR_TEMPORARILY_UNAVAILABLE` | 容量或网络问题导致无法执行。 | 稍后重新提交。 |
| `YIR_BUDGET_EXCEEDED` | 没有更多尝试能满足 Job 的 `max_cost`。 | 重新报价；如接受更高价格，在新请求中提高 `max_cost`。 |
| `YIR_INSUFFICIENT_BALANCE` | 余额在 Job 继续前耗尽，或低余额使 Job 在 `queued` 停留满 30 分钟（见[计费](/zh/docs/concepts/billing#job-如何计费)）。 | 充值后重新提交。 |
| `YIR_RATE_LIMITED` | Job 被限流。 | 稍后重新提交。 |
| `YIR_OUTCOME_TIMEOUT` | 渠道始终未确认结果，Yir 已关闭该 Job。该次尝试和迟到的结果都不收费；此前渠道已计费的尝试仍照实收费。 | 不可重试（`action: contact_support`），请提供 Job ID 联系支持。如仍需要结果，属于新请求，请用新的幂等键提交。 |
| `YIR_JOB_TIMEOUT` | Job 未在最长运行时限内完成（图片 30 分钟、视频 90 分钟），Yir 已将其关闭。仍在进行的尝试和迟到的结果都不收费；此前渠道已计费的尝试仍照实收费。 | 用新的幂等键提交新请求。 |
| `YIR_RESULT_DELIVERY_FAILED` | 结果已生成，但未能复制到 Yir 存储。 | 稍后重新提交。 |

Job 错误上的 `retryable: true` 表示**新的**请求可能成功，绝不表示同一个 Job 会被重试。用原幂等键重新提交只会返回同一个失败的 Job，因此新尝试请使用新键。

## 不在列表中的错误

遇到未知 `code` 时：`retryable` 为 `true` 则按 `YIR_TEMPORARILY_UNAVAILABLE` 处理，否则视为需要人工处理的请求问题。SDK 在发送前的校验错误有各自的错误码，见 [SDK 文档](https://github.com/yir-ai/sdk)。
