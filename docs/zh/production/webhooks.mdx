在生成请求中设置 `webhook_url`，Job 进入 `succeeded`、`failed` 或 `cancelled` 时即会收到回调。回调请求体是完整的终态 Job，与 `GET /v1/jobs/{id}` 相同，包含 `result` 和 `billing`，绝不会是渠道的原始响应。

```json
{
  "model": "openai/gpt-image-2",
  "input": { "type": "text", "prompt": "雾中的灯塔" },
  "parameters": { "resolution": "1K", "aspect_ratio": "1:1", "n": 1 },
  "webhook_url": "https://example.com/yir/webhook"
}
```

地址必须使用 HTTPS 默认端口 443。也可以在 Console 中注册最多 5 个[端点](#endpoints-and-delivery-history)，所有已启用的端点都会收到账户下全部终态事件。请求中的 `webhook_url` 会在这些端点之外额外投递；与已注册端点相同的地址只投递一次。所有投递都使用同一个账户签名密钥签名。

## 投递 Header

| Header | 说明 |
| --- | --- |
| `Yir-Webhook-Id` | 稳定的事件 ID，用于去重。 |
| `Yir-Webhook-Timestamp` | 本次投递签名时的 Unix 秒。 |
| `Yir-Webhook-Signature` | `v1=` 加上 Base64 编码的 HMAC-SHA256 签名。 |
| `Yir-Webhook-Event` | `job.succeeded`、`job.failed`、`job.cancelled` 或 `job.billing_settled`。 |
| `Yir-Webhook-Attempt` | 投递尝试序号。 |

## 校验签名

Webhook 使用账户的 **Webhook 签名密钥**签名，它与 API Key 相互独立，可在 [Console → Webhook](https://yir.ai/zh/console/webhooks) 查看。

1. 在解析 JSON 之前读取**原始请求体字节**。
2. 若 `Yir-Webhook-Timestamp` 与本机时间相差超过 300 秒，拒绝请求。
3. 计算 `HMAC-SHA256(secret, timestamp + "." + id + "." + raw_body)` 并做 Base64 编码。
4. 以常量时间比较 `"v1=" + 签名` 与 `Yir-Webhook-Signature`。

<CodeGroup>

```js Node.js
import crypto from "node:crypto";
import express from "express";

const app = express();
const secret = process.env.YIR_WEBHOOK_SECRET;

app.post("/yir/webhook", express.raw({ type: "application/json" }), (req, res) => {
  const id = req.get("Yir-Webhook-Id");
  const timestamp = req.get("Yir-Webhook-Timestamp");
  const signature = req.get("Yir-Webhook-Signature") ?? "";

  if (!id || !timestamp || Math.abs(Date.now() / 1000 - Number(timestamp)) > 300) {
    return res.sendStatus(400);
  }
  const expected = "v1=" + crypto
    .createHmac("sha256", secret)
    .update(`${timestamp}.${id}.`)
    .update(req.body)
    .digest("base64");
  const valid = expected.length === signature.length &&
    crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(signature));
  if (!valid) return res.sendStatus(400);

  const job = JSON.parse(req.body.toString("utf8"));
  // 先按 id 去重，再按 job.id 只处理一次终态。
  res.sendStatus(204);
});
```

```python Python
import base64, hashlib, hmac, os, time

SECRET = os.environ["YIR_WEBHOOK_SECRET"].encode()

def verify(headers, raw_body: bytes) -> bool:
    event_id = headers.get("Yir-Webhook-Id")
    timestamp = headers.get("Yir-Webhook-Timestamp")
    signature = headers.get("Yir-Webhook-Signature", "")
    if not event_id or not timestamp or abs(time.time() - int(timestamp)) > 300:
        return False
    message = f"{timestamp}.{event_id}.".encode() + raw_body
    digest = hmac.new(SECRET, message, hashlib.sha256).digest()
    expected = "v1=" + base64.b64encode(digest).decode()
    return hmac.compare_digest(expected, signature)
```

</CodeGroup>

SDK 提供同样的校验：TypeScript 为 `verifyWebhookSignature` 与 `constructWebhookEvent`，Go 为 `VerifyWebhookSignature` 与 `ConstructWebhookEvent`。

## 每个 Job 只处理一次

在两个层面去重：

1. **事件：** 保存 `Yir-Webhook-Id`，跳过已处理的事件；事件落库后返回 `2xx`。
2. **Job：** 轮询和 Webhook 可能报告同一个终态 Job。保存文件与费用结清后的入账分别以 `job.id` 为键去重，各自只执行一次。

仅当 `billing.status` 为 `settled` 时，`billing.total_charged_by_yir` 才是最终费用。结果立即通知；结果事件入队时费用尚未结清的，结清后另发 `job.billing_settled`，事件 ID 独立，正文仍是完整 Job。事件可能乱序：不要用待结算快照覆盖已结清费用。结果履约与最终费用入账分别按 Job ID 去重。事件名称头不在签名内容内；费用判断应依据验签后的正文 `billing.status`，或重新查询 Job。投递中的结果地址是短期链接，同一事件的不同投递可能不同，请尽快下载文件。

## 重试

接收端未返回 `2xx` 时，Yir 会自动重试。重试使用相同的事件 ID，但时间戳和签名会更新；重试不会重新提交 Job，也不会重复收费。不支持手动重新投递。

回调丢失时，只要 Job 仍在保留期内，`GET /v1/jobs/{id}` 返回当前 Job，包括最新费用。很多集成把 Webhook 当作唤醒信号，同时保留低频轮询作为兜底。

不要在日志中记录签名、密钥或结果地址。

## 端点与投递记录 [#endpoints-and-delivery-history]

[Console → Webhook](https://yir.ai/zh/console/webhooks) 集中管理账户级的端点、签名密钥和投递记录。

| 端点设置 | 规则 |
| --- | --- |
| **URL** | 公网可访问的 HTTPS 地址（端口 443），不超过 1000 个字符。同一 URL 只能注册一次。 |
| **描述** | 可选，不超过 200 个字符。 |
| **启用** | 只有已启用的端点会收到投递。停用可暂停端点而不删除它。 |

端点会收到账户下所有终态 Job 事件，包括提交时未设置 `webhook_url` 的 Job。最多可注册 5 个端点。删除端点后不再向其发送新的投递，已有记录会保留。

签名密钥可以显示、复制或轮换。轮换立即生效，旧密钥随即失效，请在轮换后立刻更新接收端。

每个端点显示总投递次数、成功率和最近一次投递。点击**查看投递记录**可列出最近的投递，每条显示事件、所属 Job（链接到[日志](/zh/docs/console#logs)）、最近一次 HTTP 状态或错误，以及尝试次数：

| 状态 | 含义 |
| --- | --- |
| 成功 | 端点返回了 `2xx` 状态。 |
| 重试中 | 投递失败，Yir 会自动重试，并显示下次重试时间。 |
| 失败 | 重试次数已用尽，或地址被拒绝（例如不是公网 HTTPS 主机），不会重试。 |

发往请求级 `webhook_url` 的投递显示在日志中对应 Job 的详情里。某个端点最近一次投递失败时，[通知](/zh/docs/console#alerts)会显示警告。
