[Console → Webhooks](https://yir.ai/zh/console/webhooks) 集中管理账户级的 Webhook 设置。回调内容、Header 与签名校验见 [Webhooks](/zh/docs/guides/webhooks)。

## 端点

端点会收到账户下所有终态 Job 事件（`job.succeeded`、`job.failed`、`job.cancelled`），包括提交时未设置 `webhook_url` 的 Job。

| 设置 | 规则 |
| --- | --- |
| **URL** | 公网可访问的 HTTPS 地址，不超过 1000 个字符。同一 URL 只能注册一次。 |
| **描述** | 可选，不超过 200 个字符。 |
| **启用** | 只有已启用的端点会收到投递。停用可暂停端点而不删除它。 |

最多可注册 5 个端点。删除端点后不再向其发送新的投递，已有投递记录会保留。

请求中的 `webhook_url` 会在这些端点之外额外投递；如果它与某个已注册端点的 URL 相同，该 Job 只向它投递一次。

## 签名密钥

所有投递（包括发往端点和请求级地址的）都使用同一个账户签名密钥签名。可以显示并复制密钥，也可以轮换。轮换立即生效，旧密钥随即失效，请在轮换后立刻更新接收端。

## 投递记录

每个端点显示总投递次数、成功率和最近一次投递。点击**查看投递记录**可列出该端点最近的投递，并按状态筛选：

| 状态 | 含义 |
| --- | --- |
| 成功 | 端点返回了 `2xx` 状态。 |
| 重试中 | 投递失败，Yir 会自动重试，并显示下次重试时间。 |
| 失败 | 重试次数已用尽，或地址被拒绝（例如不是公网 HTTPS 主机），不会重试。 |

每条记录显示事件、所属 Job（链接到其[日志](/zh/docs/console/logs)）、最近一次 HTTP 状态或错误，以及尝试次数。发往请求级 `webhook_url` 的投递显示在日志中对应 Job 的详情里。

不支持手动重新投递。投递失败时，可用 `GET /v1/jobs/{id}` 读取 Job，保留期内它始终返回同一个终态 Job。某个端点最近一次投递失败时，[告警](/zh/docs/console/alerts)会显示警告。
