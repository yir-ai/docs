RoutingProfile 定义 Yir 为 Job 选择合格渠道供应时使用的长期默认值。既有绑定保留，API Key 不再提供 Profile 选择入口，也不再创建新 Profile。默认及已有 Profile 的偏好、恢复策略和模型限制仍可编辑。

## 路由偏好

- **平衡模式**：允许 Yir 根据平台认证事实评估完整合格计划。
- **成本优先**：在请求规格可比较时优先考虑较低的公开用户价。

不再提供自定义渠道排序，由 Yir 自动选择合格渠道。

## 渠道范围和 fallback

使用 `routing.only` 指定 1–16 个渠道组成的无序白名单，选择与恢复始终留在白名单内。单元素白名单用于定点测试。旧严格 Profile 限制仍保留，请求只能进一步收窄其范围。

Fallback 决定当前 Attempt 被确认失败后，Yir 是否可以继续计划中的下一条路线。任务变慢或结果未知不会仅为触发 fallback 而被当作失败。

## 渠道版本

`routing.variants` 按渠道指定一个已登记的版本。省略某渠道的版本时，只使用它的标准版（`standard`）。同一渠道的不同版本分别绑定上游型号、价格和能力；选择版本不会改变模型公共参数。

同时提供 `routing.only` 时，版本映射中的渠道必须位于白名单内。指定版本不可用时，不会自动改用同渠道的其他版本；其他允许渠道仍遵循 fallback 规则。可用版本以模型目录为准。

## 请求级覆盖

Standard API 或 Playground 请求可以覆盖偏好和 fallback，并用 `routing.only` 收窄渠道范围。显式空列表无效；省略时使用默认允许范围。它不能突破认证、规格兼容、授权供应、运行状态、计费、安全检查和 Yir 的 Attempt 上限。

请求不能选择 Credential、AccessProvider、内部接入路径、采购价格、健康评分或任意 Attempt 数量。
