description: 用 routing 控制哪些渠道和渠道版本可以执行请求、按价格还是速度排序，以及某次尝试确认失败后如何切换渠道。
---

Yir 上的一个模型可能由多个**渠道**提供：模型厂商的官方 API，以及其他经过认证的第三方平台。每个 Job 由 Yir 选择合适的渠道；某次尝试被确认失败时，可以切换到其他渠道；设置了 `max_cost` 时不会超出它。

你可以在报价和生成请求中使用可选的 `routing` 对象影响这一过程。不提供时，使用 API Key 绑定的 Routing Profile（见 [Console 路由](/zh/docs/console#routing-profiles)）。

```json
{
  "routing": {
    "preference": "cost",
    "only": ["official", "fal"],
    "variants": { "fal": "standard" },
    "fallback": true
  }
}
```

## 字段

| 字段 | 取值 | 作用 |
| --- | --- | --- |
| `preference` | `cost`、`speed` | `cost`（默认）按估价从低到高选择渠道。`speed` 按渠道近期实测的上游生成耗时（中位数）从快到慢选择；近期样本不足的渠道排在后面，按价格排序。`balanced` 仍可使用，是 `cost` 的已弃用别名。默认取 Key 的 Routing Profile。 |
| `only` | 1–16 个渠道 ID | 无序白名单，选择与切换都限定在其中。只写一个渠道可用于定点测试。 |
| `variants` | 渠道 ID → 版本 的映射 | 选择渠道的特定版本，见下文。 |
| `fallback` | `true`、`false` | `false` 表示只允许一次渠道尝试。默认取 Key 的 Routing Profile。 |
| `fidelity` | `original`、`genuine`、`any` | 渠道输出与模型原生输出一致程度的下限，见[规格真实性](#规格真实性)。默认取 Key 的 Routing Profile。 |
| `accelerate` | `true`、`false` | 图片尝试远超该渠道常规完成时间仍无结果时，换下一条路线，见[路由加速](#路由加速)。默认取 Key 的 Routing Profile。 |

不支持自定义顺序（`order`）。无效的路由参数返回 `400 YIR_INVALID_ROUTING_OVERRIDE`。

## 渠道 ID 与 official 别名

渠道 ID 是小写标识，例如 `openai`、`google`、`fal`、`kie`。[模型市场](https://yir.ai/zh/models)的模型详情页列出了每个模型可用的渠道和版本。

`official` 是当前模型原厂渠道的别名，Yir 会在校验前解析。例如在 OpenAI 模型上，`only: ["official"]` 与 `only: ["openai"]` 等价。响应中始终返回真实渠道 ID，例如 `final_provider`。

## 渠道版本

部分渠道对同一模型提供多个版本，例如标准版和更快或更便宜的版本，各自对应不同的上游型号、价格与能力，但模型的公开参数不变。

- **未指定某渠道：** 该渠道所有符合条件的版本都可能参与。
- **`"standard"`：** 只使用该渠道的标准版。
- **其他版本名：** 只使用该版本。版本不存在或不可用时，不会替换为同一渠道的其他版本；白名单中的其他渠道仍按切换规则参与。

同时提供 `only` 时，`variants` 中的每个渠道都必须在 `only` 内。

### 不同版本可承接的请求不同

同一渠道的不同版本，计费方式和可承接的规格可能不同。例如 APIMart 的 GPT Image 2.5 标准版本按 Token 计费、承接所有画质档位，而 `ext` 版本按张固定计价、支持的画幅更少，只承接 `low` 和 `medium`。

- 不支持请求参数的版本，不会参与该请求的路由和渠道切换。如果 `only` 与 `variants` 限定后没有支持该请求的版本，报价返回 `no_matching_supply`，请求被拒绝。
- [模型市场](https://yir.ai/zh/models)按精确规格比价：版本只会出现在它支持的规格下；选择画质档位时，不承接该档位的版本会被标出。

## 规格真实性

有些渠道返回的不是模型的原生结果，例如把 1K 图放大成 4K，或用原厂的消费端应用而不是 API 出图。Yir 依据 C2PA 内容凭证和自己的实测，为每个渠道路线和档位定级；`fidelity` 设定请求能接受的最低等级：

| 取值 | 使用的渠道 |
| --- | --- |
| `genuine` | 默认。跳过已知会放大或改动输出的路线。 |
| `original` | 只用实测为原厂 API 原样输出的路线，以及原厂官方渠道。 |
| `any` | 不过滤。放大渠道往往更便宜。 |

默认值取 API Key 绑定的 Routing Profile 的 `default_fidelity`（未修改时为 `genuine`，可在 [Console](/zh/docs/console#routing-profiles) 修改）；请求里的 `routing.fidelity` 会覆盖它。过滤在 `only` 和渠道排除之后、定价之前生效，所以更严格的取值可能让价格变高。取值在 Job 准入时固定。

没有渠道满足下限时，生成请求返回 `422 YIR_FIDELITY_EXCLUDED`，报价返回 `supply.available: false` 与 `issues: ["no_matching_supply"]`。可改用 `genuine` 或 `any`，或换模型、换规格。

每个交付文件在 `result.files[].fidelity` 中给出实际检测结果：

```json
{ "url": "https://...", "media_type": "image/png", "fidelity": { "grade": "original", "reason": "vendor_signed" } }
```

| `grade` | 含义 |
| --- | --- |
| `original` | 原厂 API 输出：原厂签名有效，内容未改动。 |
| `app` | 原厂消费端应用（如 ChatGPT）输出：原厂签名有效，内容未改动。 |
| `equivalent` | 没有有效的原厂签名，但有证据表明没有被放大或改动。 |
| `altered` | 被放大、签名后被改动，或尺寸、时长不足请求规格。 |
| `unverified` | 没有证据，无法判断。 |

`reason` 是解释等级的简短机读代码。等级功能上线前交付的结果没有 `fidelity`。过滤依据的是各路线的实测等级，只能降低拿到放大结果的概率，不是保证；要把文件当作模型原图展示时，请检查 `grade`。

## 渠道切换规则

当前尝试被**确认失败**后，Yir 会切换渠道；开启[路由加速](#路由加速)时，图片尝试远超该渠道常规完成时间仍无结果，也会切换。除此之外，慢或结果未知的尝试不会为了切换而被放弃。默认情况下，一个 Job 最多尝试三个渠道（至多两个第三方、一个官方），按 `preference` 排序（官方渠道也可能排第一），同时受以下条件约束：

- 你的 `only` 与 `variants`，以及 Key 所绑定 Routing Profile 的限制；
- 各渠道支持的模型与参数；
- 渠道当前的可用性；
- 你设置的 `max_cost`：估价超过其剩余额度（扣除此前尝试已收费用）的渠道会被跳过。

提交前被跳过的渠道不计为尝试。报价中存在官方参考价，不代表一定会使用官方渠道。

**警告：过紧的 `max_cost` 可能在故障切换时中断交付。** 即使 Job 已被接受，原渠道失败后也可能需要切换到更贵的渠道。如果备选渠道的估价超过扣除此前已计费尝试后的剩余预算，Yir 会跳过它；没有其他符合预算的备选渠道时，Job 将以 `YIR_BUDGET_EXCEEDED` 失败，可能无法交付结果。若业务更重视持续交付而非单个 Job 的费用封顶，可省略此可选字段；需要上限时，应为较贵的备选渠道和此前尝试的费用留出余量。省略后没有单个 Job 的费用上限，实扣可能高于报价；账户余额及其他限制仍然适用。

## 路由加速

上游渠道偶尔会让任务卡住，远远超过平常的耗时。开启 `accelerate` 时，如果图片尝试在上游迟迟没有结果，达到该渠道近期 p99 完成时间的约两倍（至少 5 分钟；目前的图片渠道大约是 10 到 15 分钟），Yir 会中止这次尝试，改用下一条路线重试。

- **需要有下一条路线。** 加速沿用上面的切换规则：`fallback` 开启，限定在 `only` 与 `variants` 之内，不超过 `max_cost` 剩余额度和账户余额，并且未达三次尝试上限。没有下一条路线时，Yir 会继续等待当前尝试。
- **同一时间只有一次尝试。** Yir 不会并行让多个渠道竞速。被中止的尝试即使之后完成，也不会用作结果。
- **计费。** 如果被中止尝试的上游仍然计费，这笔实际费用与其他上游计费的尝试一样收取，并计入 `max_cost`。
- **仅限图片。** 视频 Job 不加速：视频单价高，被截断的尝试仍可能被上游计费。

默认值取 API Key 绑定的 Routing Profile 的 `default_accelerate`（未修改时为开启，可在 [Console](/zh/docs/console#routing-profiles) 修改）；请求里的 `routing.accelerate` 会覆盖它。设为 `{"accelerate": false}` 则始终等待第一个渠道，例如你宁可在较慢但更便宜的渠道上等，也不想冒为第二次尝试付费的风险。在 Console 日志中，被中止的尝试显示为**已加速换渠道**。

## 渠道相关的参数差异

少数参数在不同渠道上的处理方式不同。当渠道忽略你的某个参数时，Yir 会明确告知而不是隐瞒：

- 报价包含首选渠道的 `parameter_notices`；若切换渠道后处理可能不同，还会返回 `parameter_handling_may_vary: true`。
- 成功的 Job 及其 Webhook 包含实际产出结果那次尝试的 `parameter_notices`。

另一些参数会限定可执行的渠道。对 GPT Image 而言，`quality` 是最低画质档位：只有承接该档位的渠道参与路由和渠道切换，该参数不会被忽略。各模型页面列出了渠道及其可承接的档位，如 [GPT Image 2](/zh/docs/models/openai/gpt-image-2#画质) 与 [GPT Image 2.5](/zh/docs/models/openai/gpt-image-2-5-flare#画质)。

路由无法绕过认证、余额、支出上限、规格校验或 Yir 的尝试次数限制，也不能指定凭据。
