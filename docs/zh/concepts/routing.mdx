Yir 上的一个模型可能由多个**渠道**提供：模型厂商的官方 API，以及其他经过认证的第三方平台。Yir 为每个 Job 选择合格的渠道；某次尝试确认失败后，可以切换到其他渠道。设置了 `max_cost` 时，累计费用不会超出它。

在报价和生成请求中，可以用可选的 `routing` 对象调整这一过程。不提供时，使用 API Key 绑定的 Routing Profile（见 [Console 路由](/zh/docs/console#routing-profiles)）。

```json
{
  "routing": {
    "preference": "cost",
    "only": ["official", "fal"],
    "variants": { "fal": "standard" },
    "fallback": true
  }
}
```

## 字段

| 字段 | 取值 | 作用 |
| --- | --- | --- |
| `preference` | `cost`、`speed` | `cost` 按估价从低到高选择渠道。`speed` 按渠道近期实测的上游生成耗时（中位数）从快到慢选择，近期样本不足的渠道排在后面，按价格排序。默认取 Key 的 Routing Profile（未修改时为 `cost`）。`balanced` 是 `cost` 的已弃用别名，仍可使用。 |
| `only` | 1–16 个渠道 ID | 无序白名单，选择和切换都限定在其中。只写一个渠道可用于定点测试。 |
| `variants` | 渠道 ID → 版本 的映射 | 选择渠道的特定版本，见下文。 |
| `fallback` | `true`、`false` | `false` 表示只允许一次渠道尝试，未计费的内容拒绝除外（见[内容拒绝](#内容拒绝)）。默认取 Key 的 Routing Profile。 |
| `fidelity` | `original`、`genuine`、`any` | 渠道输出与模型原生输出一致程度的下限，见[规格真实性](#规格真实性)。默认取 Key 的 Routing Profile。 |
| `accelerate` | `true`、`false` | 图片尝试明显超过常规耗时仍无结果时，启动下一条路线，见[路由加速](#路由加速)。默认取 Key 的 Routing Profile。 |

不支持自定义顺序（`order`）。无效的路由参数返回 `400 YIR_INVALID_ROUTING_OVERRIDE`。

**提示：不要用 `only` 控制费用。** `only` 之外的渠道不参与切换：名单内的渠道都失败或不可用时，即使其他渠道能完成，Job 也会直接失败。要限制单个 Job 的费用，用 `max_cost`，并为备选渠道留出余量（见[报价与计费](/zh/docs/concepts/billing)）；要避开改动输出的渠道，用 `fidelity`。`only` 适合定点测试，或业务必须限定渠道的场景。

## 速度优先如何选择渠道

`routing.preference: "speed"` 只在**同一模型、当前请求规格**的可用渠道之间选择：不会换成另一个模型，也不保证每次都选到当时最快的渠道。

选择顺序如下：

1. **筛选可执行渠道。** Key 的 Routing Profile、`only`、`variants`、`fidelity`、模型参数和渠道可用性都照常生效，设置了 `max_cost` 时也受预算约束。速度优先不会绕过这些限制。
2. **优先健康渠道和请求画质。** 异常降级的渠道排在健康渠道之后。用更高画质档位承接请求、且比原画质路线更贵的路线，排在原画质路线之后兜底。
3. **比较历史上游耗时中位数（P50）。** 前两步条件相同时，有有效速度统计的路线优先，P50 越低越靠前。统计按渠道路线（含版本）和精确请求规格分别计算，不会套用其他分辨率、画幅或画质的数据。
4. **用价格决定剩余顺序。** P50 相同，或都没有有效速度统计时，按价格从低到高排序。

P50 为 30 秒，表示历史有效样本中约一半的上游执行耗时不超过 30 秒，**不是对本次请求的时限承诺**。速度统计至少需要 5 个有效耗时样本，过期的统计不参与比较；渠道当前的排队情况也可能与历史不同。

这里比较的是**上游执行耗时**。端到端等待还包括输入准备、调度和结果交付，所以 P50 不等于从提交请求到下载结果的完整耗时。

### 为什么速度优先仍会选中特价版？

“特价”只描述价格，不代表更慢。特价版的有效 P50 可能更低，也可能在候选都没有有效速度统计或 P50 相同时靠价格胜出。标准版更贵，也不保证每次更快。

`speed` 决定选择顺序；`fallback` 控制符合条件的失败后是否切换（例外见[内容拒绝](#内容拒绝)）；`accelerate` 控制图片长时间无结果时是否启动下一条路线。**速度优先不会同时请求多个渠道竞速**，也不会把普通的短暂等待当作失败。加速的触发条件和费用见[路由加速](#路由加速)。

## 自定义渠道示例

以下都是合并到报价或生成请求中的 `routing` 片段，接口要求的模型、输入等参数仍需提供。先在[模型市场](https://yir.ai/zh/models)确认所选模型和规格支持哪些渠道和版本，再用相同参数报价。换渠道或版本可能改变价格。

### 自动选快，保留全部合格渠道

```json
{
  "routing": {
    "preference": "speed",
    "fallback": true,
    "accelerate": true
  }
}
```

未提供 `only`，Key 策略允许的合格渠道全部保留。`accelerate` 只对图片生效，且需要有符合条件的下一条路线。

### APIMart 只用标准版，保留其他渠道兜底

例如请求支持 APIMart 标准版的 GPT Image 2.5 模型时：

```json
{
  "routing": {
    "preference": "speed",
    "variants": { "apimart": "standard" },
    "fallback": true
  }
}
```

这会将 APIMart 限定为当前模型的标准版，其他渠道仍参与速度排序和切换。如果只使用 APIMart，再加 `"only": ["apimart"]`。

### 只在指定渠道之间选快

```json
{
  "routing": {
    "only": ["apimart", "kie"],
    "variants": { "apimart": "standard" },
    "preference": "speed",
    "fallback": true
  }
}
```

只在 APIMart 标准版和 KIE 的合格路线之间选择和切换。`only` 是无序白名单：写在前面不代表优先，`fallback: true` 也不会放行名单外的渠道。两者都不可用时，不会调用官方或其他渠道。

要让一个 Key 长期使用相同规则，在 [Console 的 Routing Profiles](/zh/docs/console#routing-profiles) 设置速度优先和渠道排除规则，并确认 Key 绑定了该策略。可以排除整个渠道、特价档，或某个模型的特定渠道；请求级设置不能恢复 Key 策略已排除的渠道。范围越窄，可用于提速和兜底的选择越少。

## 渠道 ID 与 official 别名

渠道 ID 是小写标识，例如 `openai`、`google`、`fal`、`kie`。[模型市场](https://yir.ai/zh/models)的模型详情页列出了每个模型可用的渠道和版本。

`official` 是当前模型原厂渠道的别名，Yir 在校验前解析。例如在 OpenAI 模型上，`only: ["official"]` 与 `only: ["openai"]` 等价。响应中始终返回真实渠道 ID（如 `final_provider`）。

## 渠道版本

部分渠道对同一模型提供多个版本，例如标准版和更快或更便宜的版本。各版本的上游型号、价格和能力不同，模型的公开参数不变。

- **未指定某渠道：** 该渠道所有符合条件的版本都可能参与。
- **`"standard"`：** 只使用该渠道的标准版。
- **其他版本名：** 只使用该版本。版本不存在或不可用时，不会替换为同一渠道的其他版本；白名单中的其他渠道仍按切换规则参与。

同时提供 `only` 时，`variants` 中的每个渠道都必须在 `only` 内。

版本 ID 按模型和渠道定义。复用路由设置前，先核对目标模型。例如，Yir 将 `google/nano-banana-pro` 的 APIMart 固定价路线公开为 `standard`，对应上游别名 `nano-banana-pro-ext`。选择这条路线时传入 `"variants": { "apimart": "standard" }`。下文的 APIMart `ext` 示例适用于 GPT Image 2.5。

### 不同版本可承接的请求不同

同一渠道的不同版本，计费方式和可承接的规格可能不同。例如 APIMart 的 GPT Image 2.5 标准版按 Token 计费，承接所有画质档位；`ext` 版本按张固定计价，支持的画幅更少，只承接 `low` 和 `medium`。

- 不支持请求参数的版本不参与该请求的路由和切换。`only` 与 `variants` 限定后没有支持该请求的版本时，报价返回 `no_matching_supply`，生成请求被拒绝。
- [模型市场](https://yir.ai/zh/models)按精确规格比价：版本只会出现在它支持的规格下；选择画质档位时，不承接该档位的版本会被标出。

## 规格真实性

有些渠道返回的不是模型的原生结果，例如把 1K 图放大成 4K，或用原厂的消费端应用而不是 API 出图。Yir 依据 C2PA 内容凭证和自己的实测，为每条渠道路线和档位定级；`fidelity` 设定请求能接受的最低等级：

| 取值 | 使用的渠道 |
| --- | --- |
| `genuine` | 默认。跳过已知会放大或改动输出的路线。 |
| `original` | 只用实测为原厂 API 原样输出的路线，以及原厂官方渠道。 |
| `any` | 不过滤。放大渠道往往更便宜。 |

默认值取 API Key 绑定的 Routing Profile 的 `default_fidelity`（未修改时为 `genuine`，可在 [Console](/zh/docs/console#routing-profiles) 修改）；请求里的 `routing.fidelity` 会覆盖它。过滤在 `only` 和渠道排除之后、定价之前生效，所以更严格的取值可能抬高价格。取值在 Job 准入时固定。

没有渠道满足下限时，生成请求返回 `422 YIR_FIDELITY_EXCLUDED`，报价返回 `supply.available: false` 与 `issues: ["no_matching_supply"]`。可放宽 `fidelity`，或换模型、换规格。

每个交付文件在 `result.files[].fidelity` 中给出实际检测结果：

```json
{ "url": "https://...", "media_type": "image/png", "fidelity": { "grade": "original", "reason": "vendor_signed" } }
```

| `grade` | 含义 |
| --- | --- |
| `original` | 原厂 API 输出：原厂签名有效，内容未改动。 |
| `app` | 原厂消费端应用（如 ChatGPT）输出：原厂签名有效，内容未改动。 |
| `equivalent` | 没有有效的原厂签名，但有证据表明没有被放大或改动。 |
| `altered` | 被放大、签名后被改动，或尺寸、时长不足请求规格。 |
| `unverified` | 没有证据，无法判断。 |

`reason` 是解释等级的简短机读代码。等级功能上线前交付的结果没有 `fidelity`。过滤依据的是各路线的实测等级，只能降低拿到放大结果的概率，不能完全避免；要把文件当作模型原图展示时，请检查 `grade`。

## 渠道切换规则

当前尝试**确认失败**后，Yir 会切换渠道；开启[路由加速](#路由加速)时，图片尝试明显超过常规耗时仍无结果，也会启动下一条路线。除此之外，Yir 不会因为尝试慢或结果未知而放弃它。默认情况下，一个 Job 最多尝试三个渠道（至多两个第三方、一个官方），按 `preference` 排序（官方渠道也可能排第一），同时受以下条件约束：

- 你的 `only` 与 `variants`，以及 Key 所绑定 Routing Profile 的限制；
- 各渠道支持的模型与参数；
- 渠道当前的可用性；
- 你设置的 `max_cost`：估价超过剩余额度（扣除此前尝试已收费用）的渠道会被跳过。

提交前被跳过的渠道不计为尝试。报价中存在官方参考价，不代表一定会使用官方渠道。

### 内容拒绝

各渠道的内容审核宽严不一，一个渠道拒绝的提示词在另一个渠道可能通过。渠道因内容安全拒绝提示词或参考图、**且没有对该次尝试计费**时，即使 `fallback: false`，Yir 也会再尝试最多两个渠道。这些尝试同样限定在 `only`、`variants`、Key 的 Routing Profile 和 `max_cost` 之内，不占三次尝试上限，也不会重试拒绝过的渠道。未计费的拒绝不收费。没有渠道接受或已无渠道可换时，Job 以 `YIR_CONTENT_REJECTED` 失败。渠道已计费或无法确认是否计费的拒绝（如生成后才拦截输出），以及 Yir 自身对参考图的检查拦下的，直接结束 Job、不切换渠道。

**警告：过紧的 `max_cost` 可能在故障切换时中断交付。** Job 被接受后，原渠道失败时仍可能需要切换到更贵的渠道。备选渠道的估价超过剩余预算（扣除此前已计费尝试）时，Yir 会跳过它；没有其他符合预算的备选渠道时，Job 以 `YIR_BUDGET_EXCEEDED` 失败，可能无法交付结果。如果持续交付比单个 Job 的费用封顶更重要，可省略 `max_cost`；需要上限时，为较贵的备选渠道和此前尝试的费用留出余量。省略后单个 Job 没有费用上限，实扣可能高于报价，账户余额及其他限制仍然适用。

## 路由加速

上游渠道偶尔会让任务卡住，耗时远超平常。开启 `accelerate` 时，图片尝试到截断时限仍没有结果，Yir 会启动下一条路线。截断时限按该渠道和规格的近期耗时计算，通常为 1.5 到 13 分钟，渠道变慢时可能更短。

- **需要有下一条路线。** 加速沿用上面的切换规则：`fallback` 开启，限定在 `only` 与 `variants` 之内，不超过 `max_cost` 剩余额度和账户余额，并且未达三次尝试上限。没有下一条路线时，Yir 继续等待当前尝试。
- **每个 Job 最多加速一次。** 只有估价较低的图片尝试才会加速。
- **先出结果的交付。** 被截断的尝试不会取消，可能与下一条路线同时运行，先出结果的一方用于交付，每个 Job 只交付一份结果。下一条路线失败时，原尝试的结果也可以收回交付。
- **计费。** 两次尝试的上游都计费时，两笔实际费用都会收取，并计入 `max_cost`。
- **仅限图片。** 视频 Job 不加速：视频单价高，被截断的尝试仍可能被上游计费。

默认值取 API Key 绑定的 Routing Profile 的 `default_accelerate`（未修改时为开启，可在 [Console](/zh/docs/console#routing-profiles) 修改）；请求里的 `routing.accelerate` 会覆盖它。设为 `false` 后不会因耗时过长换渠道，适合宁可在较慢但更便宜的渠道上等、也不想为第二次尝试付费的场景。在 Console 日志中，被截断的尝试显示为**已加速换渠道**。

## 渠道相关的参数差异

少数参数在不同渠道上的处理方式不同。渠道忽略你的某个参数时，Yir 会明确告知：

- 报价包含首选渠道的 `parameter_notices`；若切换渠道后处理可能不同，还会返回 `parameter_handling_may_vary: true`。
- 成功的 Job 及其 Webhook 包含实际产出结果那次尝试的 `parameter_notices`。
- 渠道多给且结果仍可用时，Yir 照常交付、不判失败，并附 `disposition: "exceeded"` 的通知，收费不超过报价：
  - 张数多于 `n`：只交付最后 `n` 张（`output_count_exceeded`）。
  - 画幅相同、分辨率更高：照常交付（`resolution_exceeded`）。
  - 请求 `generate_audio: false` 却带音轨的视频：照常交付（`audio_included`）。
  - 请求 `texture: "none"` 或 `pbr: false` 却带贴图或 PBR 贴图的 3D 模型：照常交付（`texture_included`、`pbr_included`）。
- 张数不足、画幅或时长不符、分辨率更低、要求有声却静音，仍判失败。

另一些参数会限定可执行的渠道。对 GPT Image 而言，`quality` 是最低画质档位：只有承接该档位的渠道参与路由和切换，该参数不会被忽略。各模型页面列出了渠道及其可承接的档位，如 [GPT Image 2](/zh/docs/models/openai/gpt-image-2#画质) 与 [GPT Image 2.5](/zh/docs/models/openai/gpt-image-2-5-flare#画质)。

路由无法绕过认证、余额、支出上限、规格校验或 Yir 的尝试次数限制，也不能指定凭据。
