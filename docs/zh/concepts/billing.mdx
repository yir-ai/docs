## 请求三价

仅输出估算示例为 `{"kind":"estimate","amount":"0.042390","estimate":{"scope":"output_only","output_tokens":1413}}`。金额根据本次请求的预计生成输出 Token 数与当前费率计算，不包含输入等其他费用。它不是整单价格或授权上限，不能单独用来冻结零售积分或设置 `max_cost`。缺少用量依据或适用费率时返回不可报价，不虚构估价。

图片使用 `POST /v1/images/quotes`，视频使用 `POST /v1/videos/quotes`。Quote 与生成接口校验相同的模型、输入和 `parameters`，但不接受 `max_cost` 或 `webhook_url`，不创建 Job、不冻结资金，也不锁价。

| 字段 | 含义 |
| --- | --- |
| `primary` | 当前首选尝试执行整份请求的价格。 |
| `max` | 当前选中尝试的最高整单价格，不是价格之和或全目录最高价。 |
| `official` | 同规格官方参考价，不保证存在可执行的官方渠道。 |

金额使用 USD 十进制字符串。固定价格示例为 `{"amount":"0.02","kind":"fixed","reason":""}`；不可报价示例为 `{"amount":null,"kind":"unavailable","reason":"candidate_price_unavailable"}`。未知价格不是零；任一选中尝试价格未知时，`max` 不能用其余已知价格近似。

Quote 只提供本次请求需要的价格与供应信息，不公开内部渠道列表、排名、采购折扣或容量。参数合同随 SDK 版本静态提供，不在运行时下载校验代码。节省比例由接入方自行计算。

## 授权与冻结

生成请求的 `max_cost` 是整单授权上限，例如 `"0.25"` 表示最多 US$0.25，使用非负十进制字符串，最多六位小数。Submit 重新检查当前供应和价格，Quote 未过期也不保证原价格可执行。

价格与费用上界不同。只有 `has_verifiable_upper_bound` 为真时，才能将 `single_attempt_upper_bound` 作为选中尝试的最大单次费用上界。否则该字段为 `null`，不能当作零或空字符串。估算价格不能承诺最终费用上限。

新 Job 按可准入尝试的最大单次费用上界冻结一次，后续顺序尝试共用冻结，不累加各次上界。不传 `max_cost` 时按准入时的最大单次上界固化授权；显式授权更大金额不会冻结全部多余金额。无法证明费用上界时，不应自动提交。

后续路线仍须满足原授权与冻结额度，不因涨价追加扣款；没有可执行路线时失败，预算不足可返回 `YIR_BUDGET_EXCEEDED`。`routing.fallback: false` 关闭后续尝试。

目标策略为最多两个不同非官方渠道，再由一个官方渠道兜底，依次执行。所有路线均受规格、凭据、容量和预算约束；提交前跳过的路线不计 Attempt。存在官方参考价不代表兜底一定可用。

## 结算与停止

上游明确失败不收费。成功交付只结算交付结果对应费用并释放余额；最终失败或取消释放全部冻结。新 Job 到达终态时客户费用同时确定，无需另行轮询财务状态。历史任务保留原有结算事实。

短暂超时不能直接认定失败或重复提交。长时间仍无法确认的异常由 Yir 按失败零收费处理，并冻结异常渠道、通知管理员。迟到的上游成本由 Yir 内部承担，不追加客户费用。

用户停止后显示“已请求停止”：停止后续尝试，当前尝试仍可能成功并交付、结算。已按最终超时失败处理的任务不会因迟到结果再次扣款。SDK 本地 Abort 只停止本地等待或网络操作，不代替远程取消，也不代表退款完成。

## 应用定价与恢复

Pilio 可以按 `primary` 向用户定价、按最大单次上界授权采购，承担兜底价差，不追加用户积分。未交付结果退回对应积分；多结果任务按预分配的结果份额退款。

提交前持久化请求与幂等键。响应丢失时使用相同请求、相同键恢复；修改金额或参数属于新请求，不能为了绕过未知提交状态直接换键重试。终态 Job 的 `billing.max_cost` 返回固化授权；历史缺失值不能用当前价格补写。
