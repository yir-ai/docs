Yir 只对已交付的结果收费。提交前可以先报价；提交时，Yir 最多预留一次尝试所需的资金，Job 结束后释放未使用部分。

## 获取报价

把准备提交的请求体发送到报价接口：

| 操作 | 接口 |
| --- | --- |
| 单个图片请求 | `POST /v1/images/quotes` |
| 单个视频请求 | `POST /v1/videos/quotes` |
| 最多 20 个图片或视频请求 | `POST /v1/quotes` |

报价与提交使用相同的模型、输入和参数校验，但不创建 Job、不预留资金，也不锁定价格。报价请求不接受仅用于提交的 `max_cost` 和 `webhook_url`。

```json
{
  "object": "quote",
  "model": "openai/gpt-image-2",
  "currency": "USD",
  "supply": { "available": true, "requires_max_cost": false, "issues": [] },
  "primary": { "kind": "fixed", "amount": "0.04" },
  "max": { "kind": "fixed", "amount": "0.05" },
  "official": { "kind": "fixed", "amount": "0.053" },
  "single_attempt_upper_bound": "0.05",
  "has_verifiable_upper_bound": true,
  "expires_at": 1790000300
}
```

以上数值仅为示意。金额是美元十进制字符串，请使用十进制运算而非浮点数。

### 字段含义

| 字段 | 含义 |
| --- | --- |
| `primary` | Yir 首选渠道的价格。 |
| `max` | 本次请求可用渠道中的最高价格，不是多次尝试之和。 |
| `official` | 模型原厂的参考价格，仅供对比，不代表会使用官方渠道执行。 |
| `price_difference_percent` | 可选，与 `official` 的对比，负数表示 Yir 更便宜。 |
| `single_attempt_upper_bound` | 在所有可用渠道上经过验证的单次尝试费用上限；只要有一个渠道无法确定上限即为 `null`。 |
| `supply.available` | 当前没有渠道能执行此请求时为 `false`，并带有 `issues: ["no_matching_supply"]`。 |
| `supply.requires_max_cost` | 可用的用量计费渠道无法提供可核验的完整请求费用上限时为 `true`，提交时必须携带不低于 `0.01` 的 `max_cost`。 |

每个价格属于以下三类之一：

- `fixed`：本次请求的完整价格。
- `estimate`：仅覆盖**生成输出**，用于按用量计费的模型（`estimate.output_tokens` 或 `estimate.output_megapixels` 说明估算假设）。不含输入及其他费用，不能当作总价或支出上限。
- `unavailable`：`amount` 为 `null`。未知价格绝不等于零。

## 设置支出上限

生成请求中的 `max_cost` 是整个 Job 可收取的最高金额，例如 `"0.25"` 表示 0.25 美元，最多六位小数。

- **省略时：** Yir 在准入时采用可用渠道中经过验证的最高单次尝试上限。
- **必须提供：** 报价返回 `requires_max_cost: true` 时。
- **过低时：** 低于首选渠道价格的上限会被拒绝。切换渠道时会跳过超出上限的渠道；没有剩余渠道时，Job 以 `YIR_BUDGET_EXCEEDED` 失败。

提交时会重新检查价格。之前获得的报价不保证相同的价格或可用性；价格上涨也不会让 Job 收费超过你的授权。

## Job 如何计费

以下预留规则适用于省略 `billing_mode` 的请求。显式实际计费使用下一节的收款规则。

1. **准入**时预留一笔金额：可用渠道中最高的单次尝试上限，并受 `max_cost` 约束。多次尝试共用这一笔预留，不会累加。
2. **成功**时只收取交付结果那次尝试的费用，释放其余部分。
3. **失败或取消**时释放全部预留，客户费用为零。
4. 尝试进行中**请求停止**：该次尝试仍可能成功并收费。见[取消](/zh/docs/concepts/task-lifecycle#取消)。

用量计费渠道没有可核验上限时，Yir 会完整预留显式提供的 `max_cost`。仅输出估算不作为这笔预留的依据。

## 按实际费用支付

对支持的渠道，在报价和生成请求中都明确传入 `"billing_mode": "actual"`。这表示授权支付最终成功交付结果的完整实际费用，包括生成后才确定的费用。该模式不能同时传 `max_cost`，没有客户支出上限。

首批支持 Kling 2.6、3.0 Motion Control 的 KIE、APIMart 渠道，以及 FLUX 2 Pro 图片编辑的 FAL 渠道。必须用 `routing.only` 明确选择对应渠道，例如 FAL 编辑使用 `["fal"]`；其他模型或渠道会拒绝此模式。原有参数、素材和文件校验继续适用。

准入时要求钱包可用余额大于零且没有欠款，不按估算冻结总额。成功交付后，Yir 根据该任务的权威账单及本次尝试冻结的折扣，记录一笔最终收费。钱包不足支付的部分记为任务欠款；后续手动充值优先偿还最早欠款，偿还不会对同一 Job 再收一次费。有欠款时拒绝新 Job，已经准入的任务仍按保存的授权完成。此模式不启用银行卡自动扣款。

失败、取消和非 winner 尝试的成本仍由 Yir 承担。账单缺失或冲突进入费用核对，未知费用不会按零或估算结算。Job 响应中的 `billing.billing_mode: "actual"` 表示保存的授权；同一幂等键重试不能改变计费模式。历史 Job 和省略该字段的请求保留原合同。

Job 进入终态时计费即为最终结果。读取终态 Job 的 `billing`：

| 字段 | 含义 |
| --- | --- |
| `billing.total_charged_by_yir` | 此 Job 的最终收费金额。 |
| `billing.compute_charges` | 算力费用明细。新 Job 有一条由 `yir` 计费的 `managed` 条目，`status` 为 `settled`；费用免除时为 `waived`，金额为 `0.000`。数组可以为空。 |
| `billing.gateway_fee` | 网关费用：`amount` 与 `status`（`settled` 或 `waived`）。 |
| `billing.currency` | 固定为 `USD`。 |
| `billing.max_cost` | 适用的授权上限，不是收费金额。 |
| `billing.savings` | 可选，与准入时冻结的用户价对比；切换渠道后可能为负数。 |
| `billing.official_comparison` | 可选，与准入时冻结的本次请求完整官方价对比。 |

失败尝试的成本，以及 Yir 关闭 Job 后才到达的渠道结果成本，均由 Yir 承担。

## 账户与 Key 的限制

- **余额。** Job 需要足够的可用余额完成预留，否则以 `402 YIR_INSUFFICIENT_BALANCE` 拒绝。请在 Console 充值；Yir 不会自动扣款或自动充值。可以在账单页设置低余额邮件提醒。
- **每个 API Key 的月度支出上限。** 可选，在 [Console → API Keys](/zh/docs/console/api-keys) 设置。准入时把新 Job 的预留加上该 Key 当前 UTC 自然月已结算费用和在途预留；超过上限时请求以 `403 YIR_SPEND_LIMIT_EXCEEDED` 失败，不创建 Job。进行中的 Job 不会被中断。

## 为自己的产品定价

如果你向自己的用户转售生成能力，请把零售价格和退款规则与 Yir 的授权分开。可以把 `fixed` 的 `primary` 价格作为定价依据；`estimate` 仅覆盖输出，不可充当完整价格。只有在 `has_verifiable_upper_bound` 为 `true` 时才用 `single_attempt_upper_bound` 授权；否则应显式设置业务能够接受的 `max_cost`。对每个 Job 只核对一次 `total_charged_by_yir`。
