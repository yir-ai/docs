## 为官方渠道的参考视频报价

向 `POST /v1/videos/quotes` 提交请求，用 `routing.only: ["bytedance"]` 或 `["official"]` 选择字节跳动官方渠道。该渠道的参考生视频支持 `480p` 和 `720p`，需要明确画幅，且至少包含一张参考图或一段参考视频。`task_type` 使用默认的 `auto`。报价时可以传已就绪的 `file_id` 让 Yir 使用实测时长，也可以像下面这样在 URL 引用上声明输入时长。

```json
{
  "model": "bytedance/seedance-2.5",
  "input": {
    "type": "reference",
    "prompt": "一只纸船顺流而下，运动参考 @video1",
    "references": [
      { "role": "reference_video", "url": "https://example.com/reference.mp4", "duration_seconds": 5 }
    ]
  },
  "parameters": {
    "duration": 5,
    "resolution": "720p",
    "aspect_ratio": "16:9",
    "generate_audio": false
  },
  "routing": { "only": ["bytedance"] }
}
```

`parameters.duration` 是输出时长，固定时长取 4–30 的整数秒。`input.references[].duration_seconds` 用于在按 URL 报价时声明输入媒体的时长。`generate_audio` 放在 `parameters` 里。省略 `routing` 会沿用 API Key 的路由配置，也可用 [`routing.only`](/zh/docs/concepts/routing#字段) 选择 `apimart`、`kie` 等公开渠道。各输入模式支持的参数以模型合同为准。

## 任务类型

`reference` 模式下，`parameters.task_type` 告诉模型如何使用参考素材，对应字节官方的 `omni_reference_task_type`：

| 取值 | 用途 | 约束 |
| --- | --- | --- |
| `auto`（默认） | 模型根据素材和提示词自行判断。 | 上游明确拒绝编辑参数时，Yir 返回 `YIR_INPUT_REJECTED` 并停止兜底。 |
| `reference` | 参照图片、视频、音频生成新视频。 | `duration` 需要取固定值。请报价查看哪些渠道支持这个显式任务类型。 |
| `edit` | 修改参考视频，例如替换其中的主体。 | 需要 4–30 秒的 `reference_video`；`duration` 与 `aspect_ratio` 跟随原视频（省略或传 `"auto"`）。走 APIMart 和 KIE 渠道。 |
| `extend` | 延长参考视频。 | 需要 `reference_video`；`aspect_ratio` 跟随原视频，`duration` 为新增部分的秒数。走 APIMart、KIE 和 NanoAPI 渠道。 |

参考视频每段 2–30 秒、合计不超过 30 秒；参考音频合计不超过 30 秒。Yir 按实测时长比较，30.03 秒的素材也会被拒。超限的上传文件在报价与提交时返回 `YIR_INVALID_REQUEST`（字段 `input.references[i]`）；URL 素材在导入实测后失败，不会提交到上游。

模型仍会读提示词。读起来像编辑的提示词（如 "replace the dog in @video1"、"copy @video1 exactly"）在 `reference` 下可能被拒，或保留原视频里的主体。想保留动作、换掉主体时，描述动作并说明主体来自哪里（如 "the dog from @image1 trots down the stairs like the dog in @video1"），或改用 `edit`。

## 时长跟随参考视频

视频编辑时，使用 `input.type: "reference"`，至少提供一个 `reference_video`，并设置 `parameters.duration: "auto"`。将 `aspect_ratio` 设为 `"auto"` 或省略；自动时长不接受固定画幅。上游模型根据提示词判断请求是否属于编辑。纯文本、首帧和仅含图片的参考输入不能使用此选项。

Quote 接受公开 HTTPS 参考视频 URL，但不会下载素材。设置 `duration: "auto"` 且任一参考视频为 URL 时，供给可以可用，同时 `primary.amount` 和 `official.amount` 为 `null`，不返回 `expected_amount`。需要基于实测时长的估价时，请先上传视频并使用已就绪的 `file_id`。Submit 仍会先导入、校验并测量 URL 素材，再进行准入；未知估价不会绕过显式 `max_cost` 或其他预算限制。Quote 和 Job（包括 Webhook）均回显 `parameters.duration: "auto"`，不会替换成内部实测秒数；数值请求仍回显数值。

估价和准入按最长实测参考视频时长向上取整为秒，并限制在模型的 4–30 秒范围内。最终费用按实际上游金额结算，估价秒数不保证输出时长。

省略 `duration` 仍使用默认 4 秒；显式整数时长保持既有行为。不要向 Yir 传入上游的 `-1` 值。

模型合同的所有模式均接受 `parameters.resolution: "1080p"`。请对完整请求报价，查看支持该模式和分辨率的渠道。官方渠道的文生视频支持 1080p。省略 `resolution` 时使用 `720p`。官方 1080p 无视频输入费率为每百万视频 token 11.70 美元；16:9、24 fps、4 秒的输出估价为 2.27448 美元，最终按任务实际费用结算。该文生路线同时支持精确尺寸 `parameters.size: "1920x1080"`（AI SDK 的 `resolution: "1920x1080"`），绑定 1080p、16:9；与此冲突的画幅／档位及其他像素尺寸会明确拒绝。

## 原生 4K

经 APIMart 或 KIE 调用时，将 `parameters.resolution` 设为 `"4K"`。文生和参考生使用 `aspect_ratio: "16:9"`。图生使用 `auto` 并跟随首帧。需要横屏时请提供 16:9 的首帧。

原生输出采用 10-bit HEVC 编码。用于浏览器预览或后期编辑时，请确认播放器支持 HEVC。带参考视频时，估价计入输入和输出时长。报价可以用已就绪的 `file_id`，也可在 URL 引用中声明时长。最终按所用渠道的任务实扣结算。
