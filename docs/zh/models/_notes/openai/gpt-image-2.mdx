## 画质

`quality` 表示你需要的最低画质档位。Yir 把它当作路由约束：不会忽略，也不会降档。

- **不传：** 所有渠道都可执行。能设置画质的渠道按 `medium` 生成，报价按 `medium` 估算。
- **传入档位：** 只有能承接该档位的渠道参与路由和渠道切换；一条都没有时，报价返回 `no_matching_supply`，生成请求被拒绝。
- **不接受 `auto`。** `auto` 由上游自行决定档位，费用无法可靠报价；需要默认行为时请不传 `quality`。

| 渠道 | 可承接的档位 |
| --- | --- |
| 官方渠道（`openai`） | `medium`、`high` |
| APIMart `official` 版本 | `medium`、`high` |
| APIMart 标准版本、KIE | `low`、`medium` |

APIMart 标准版本和 KIE 没有画质开关，以不低于 `medium` 的固定画质出图，因此按各自的每张价格承接 `low` 和 `medium`。`high` 只会走官方渠道或 APIMart `official` 版本。

```json
{
  "model": "openai/gpt-image-2",
  "input": { "type": "text", "prompt": "A product photo of a ceramic mug" },
  "parameters": { "resolution": "1K", "aspect_ratio": "1:1", "quality": "high", "n": 1 }
}
```

模型详情（`GET /v1/models/openai/gpt-image-2`）在 `channel_parameters[].parameter_rules.quality.values` 中列出各渠道可承接的档位。在[模型市场](https://yir.ai/zh/models)选择画质档位时，不承接该档位的渠道会被标出。

按旧策略准入的 Job 仍可能在 `parameter_notices` 中带有 `quality_requires_official_channel` 通知，新 Job 不再产生。

## 与 OpenAI API 的差异

请求采用 Yir 的[通用请求格式](/zh/docs/models/official-api-differences)，按 OpenAI Images API 编写的代码需要做以下调整：

| OpenAI | Yir |
| --- | --- |
| `quality: "auto"`（OpenAI 默认值） | 不接受。改用 `low`、`medium` 或 `high`，或省略 `quality`。见[画质](#画质)。 |
| `size`（像素尺寸或 `auto`） | `resolution` 加 `aspect_ratio`。 |
| `n` 大于 1 | `n` 固定为 `1`；每张图提交一个 Job。 |
| `background`、`output_format`、`output_compression`、`moderation` | 不可用。 |
| `stream`、`partial_images` | 不可用；结果在 Job 结束时返回。 |
| 局部重绘的 `mask` | 不可用；用 `reference_image` 参考图和提示词编辑。 |
| 图片 URL 或 base64 输入 | 传公开 HTTPS `url`，或通过 [Files API](/zh/docs/guides/input-files) 上传后传 `file_id`；不接受 base64。 |

## 计费

- 按 Token 计费的渠道（官方渠道与 APIMart `official` 版本）返回仅含输出的估价：价格 `kind` 为 `estimate`，`estimate.scope` 为 `output_only`。估价按请求的档位计算，不传 `quality` 时按 `medium`。
- 按 Token 计费的渠道会把参考图另按图片输入 Token 计费。OpenAI 大致按 32×32 像素块计算输入图 Token，单张有上限；估价不包含这部分。
- 按张固定计价的渠道返回 `kind: fixed`，档位不影响价格。
- 最终费用为每次渠道计了费的尝试的上游实际费用 × 你的折扣之和，通常只有交付结果的那次，见[报价与计费](/zh/docs/concepts/billing)。
