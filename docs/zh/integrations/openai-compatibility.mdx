title: OpenAI 兼容与 new-api
description: 用 OpenAI Images 和 Sora Videos 协议调用 Yir，new-api 只需新建一个 OpenAI 渠道。
---

Yir 在 `https://gateway.yir.ai/openai` 提供 OpenAI Images 与 Sora `/v1/videos` 兼容接口。已经按 OpenAI 协议对接的系统只需更换 Base URL 和 Key；new-api（v0.13.x 与 v1.0 RC 均已验证）新建一个 OpenAI 类型渠道即可接入，无需插件或改代码。

兼容接口在内部调用 Standard API，Job、路由和计费规则与本文档其他部分一致。需要异步提交、Webhook 或完整路由控制时，请直接使用 Standard API。

## new-api 渠道配置

| 配置项 | 填写 |
|---|---|
| 渠道类型 | OpenAI |
| Base URL | `https://gateway.yir.ai/openai` |
| 密钥 | Yir API Key（`yir_sk_…`），在 Console 的 API Keys 页面创建 |
| 模型 | 要开放的 Yir 模型 ID，可用「获取模型列表」拉取 |

- **获取模型列表**只列出当前有供应的模型，使用标准 ID；别名在调用时同样可用。
- **余额查询**返回该 Key 所属账户的可用余额（美元）。
- **渠道测试**保持默认端点即可：Yir 只检查网络、Key 与该模型当前是否有供应，不生成内容、不扣费。不要把端点改成「图片生成」，那会真实出图并计费。Yir 不提供对话能力，正常的 chat 请求返回 404。

直接用 OpenAI SDK 调用时，`base_url` 填 `https://gateway.yir.ai/openai/v1`。

## 模型名

- 使用 Yir 模型 ID 或别名，例如图片 `gpt-image-2`、`google/nano-banana-2`，视频 `bytedance/seedance-1.5-pro`、`google/veo-3.1-fast-generate-001`。完整列表见[模型](/zh/docs/models)。
- **视频模型请用带厂商前缀的 ID。** new-api 内置的 Kling、Veo 等插件会接管与它们同名的模型（如 `kling-*`、`veo-*`），导致请求不走 Yir 渠道。
- 想对终端用户展示自己的模型名时，用 new-api 渠道的「模型重定向」映射到 Yir 模型 ID。

## 图片

`POST /v1/images/generations`（JSON）与 `POST /v1/images/edits`（multipart，`image` 或 `image[]`，最多 16 张）。

| 参数 | 说明 |
|---|---|
| `size` | `宽x高`，按模型能力就近匹配分辨率档位和画幅（如不支持 3:2 的模型把 `1536x1024` 落到 4:3），不会把横图改成竖图；模型没有该方向的画幅时返回 400。不传或 `auto` 用模型默认值 |
| `quality` | `low` / `medium` / `high`（`hd` 视作 `high`），模型没有对应档位时用模型默认值 |
| `response_format` | `url`（默认）或 `b64_json`。结果超过 12 MB 时 `b64_json` 退回 `url` |
| `n` | 只支持 1 |
| `resolution`、`aspect_ratio` | Yir 扩展字段，直接指定档位与画幅（如 `4K`、`21:9`），优先于 `size` |

请求同步等待出图，最长 10 分钟，期间每 10 秒发送一个换行保持连接。成功返回 `{created, data: [{url} | {b64_json}]}`。

## 视频

`POST /v1/videos`（JSON 或 multipart）、`GET /v1/videos/{id}`、`GET /v1/videos/{id}/content`。

| 参数 | 说明 |
|---|---|
| `seconds` | 视频秒数。不传时按 Sora 默认 4 秒，模型不支持 4 秒时用模型默认值。请与 new-api 计费设置保持一致 |
| `size` | `宽x高`，按短边匹配 480p / 720p / 1080p / 4K，并按同一方向就近匹配画幅 |
| `input_reference` | multipart 上传一张图作为首帧 |
| `resolution`、`aspect_ratio`、`generate_audio` | Yir 扩展字段 |

提交后立即返回 `id`（即 Yir Job ID）。new-api 会自动轮询，并通过 `/content` 下载结果，支持 Range。

## 计费

- 与 Standard API 相同，按渠道实际计费 × 折扣收费，渠道未计费的尝试不收费，见[计费](/zh/docs/concepts/billing)。
- 在 new-api 侧按自己的售价配置：图片按次，视频按秒，可参考 Yir 模型页同规格价格。
- 建议在 Console 给这个 Key 设置月度支出上限，防止配置错误造成意外消耗。

## 已知限制

- 结果链接 15 分钟内有效，适合拿到即下载；需要长期保存请用 `b64_json` 或自行转存。
- 图片同步等待超过 10 分钟会返回超时错误，Job 仍会继续，成功后照常计费；终端中途断开也一样。请凭响应头 `X-Yir-Job-Id` 对账。
- new-api 非流式中转在出图完成前不会向终端发送数据。出图较慢时，终端客户端的超时应设到 10 分钟以上，或改用 `stream: true`（v1.0 RC 会转成流式返回）。
- 暂不支持 `n > 1`、`mask` 和 JSON 格式的图片编辑。
- 结果链接与响应头里能看出 Yir；不希望暴露时请用 `b64_json`。

## 排障

| 返回 | 含义 |
|---|---|
| 400 `invalid_request_error` | 参数不被该模型支持（尺寸、秒数、质量等），按消息调整 |
| 401 | Yir Key 无效，new-api 会自动禁用渠道 |
| 402 `insufficient_quota` | 余额不足，new-api 会自动禁用渠道；充值后重新启用 |
| 403 | Key 月度上限已到 |
| 503 | 暂无可用供应，new-api 会换渠道重试 |
| 200 且带 `error` | Job 已执行但失败（如内容审核拦截），只按渠道实际计费收费，通常为零 |

反馈问题时请附上响应头 `X-Yir-Job-Id`。
