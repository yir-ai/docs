---
title: Webhooks
description: Receive the terminal Job by HTTPS callback, verify its signature, and process it exactly once.
---

Set `webhook_url` on a generation request to receive the Job when it reaches `succeeded`, `failed`, or `cancelled`. The callback body is the complete terminal Job, the same as `GET /v1/jobs/{id}`, including `result` and `billing`. It is never a raw provider response.

```json
{
  "model": "openai/gpt-image-2",
  "input": { "type": "text", "prompt": "A lighthouse in fog" },
  "parameters": { "resolution": "1K", "aspect_ratio": "1:1", "n": 1 },
  "webhook_url": "https://example.com/yir/webhook"
}
```

The URL must use HTTPS. You can also register up to 5 [endpoints](#endpoints-and-delivery-history) in Console; every enabled endpoint receives all terminal events for your account. A request's `webhook_url` is delivered in addition to those endpoints, and a URL that matches a registered endpoint is delivered only once. All deliveries are signed with the same account signing secret.

## Delivery headers

| Header | Description |
| --- | --- |
| `Yir-Webhook-Id` | Stable event ID. Use it to deduplicate. |
| `Yir-Webhook-Timestamp` | Unix seconds when this delivery was signed. |
| `Yir-Webhook-Signature` | `v1=` followed by a Base64 HMAC-SHA256 signature. |
| `Yir-Webhook-Event` | `job.succeeded`, `job.failed`, or `job.cancelled`. |
| `Yir-Webhook-Attempt` | Delivery attempt number. |

## Verify the signature

Webhooks are signed with your account's **Webhook signing secret**, which is separate from your API Key. Find it in [Console → Webhooks](https://yir.ai/console/webhooks).

1. Read the **raw request body bytes** before parsing JSON.
2. Reject the request if `Yir-Webhook-Timestamp` is more than 300 seconds from your clock.
3. Compute `HMAC-SHA256(secret, timestamp + "." + id + "." + raw_body)` and Base64-encode it.
4. Compare `"v1=" + signature` with `Yir-Webhook-Signature` in constant time.

<CodeGroup>

```js Node.js
import crypto from "node:crypto";
import express from "express";

const app = express();
const secret = process.env.YIR_WEBHOOK_SECRET;

app.post("/yir/webhook", express.raw({ type: "application/json" }), (req, res) => {
  const id = req.get("Yir-Webhook-Id");
  const timestamp = req.get("Yir-Webhook-Timestamp");
  const signature = req.get("Yir-Webhook-Signature") ?? "";

  if (!id || !timestamp || Math.abs(Date.now() / 1000 - Number(timestamp)) > 300) {
    return res.sendStatus(400);
  }
  const expected = "v1=" + crypto
    .createHmac("sha256", secret)
    .update(`${timestamp}.${id}.`)
    .update(req.body)
    .digest("base64");
  const valid = expected.length === signature.length &&
    crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(signature));
  if (!valid) return res.sendStatus(400);

  const job = JSON.parse(req.body.toString("utf8"));
  // Deduplicate by id, then apply the terminal Job once by job.id.
  res.sendStatus(204);
});
```

```python Python
import base64, hashlib, hmac, os, time

SECRET = os.environ["YIR_WEBHOOK_SECRET"].encode()

def verify(headers, raw_body: bytes) -> bool:
    event_id = headers.get("Yir-Webhook-Id")
    timestamp = headers.get("Yir-Webhook-Timestamp")
    signature = headers.get("Yir-Webhook-Signature", "")
    if not event_id or not timestamp or abs(time.time() - int(timestamp)) > 300:
        return False
    message = f"{timestamp}.{event_id}.".encode() + raw_body
    digest = hmac.new(SECRET, message, hashlib.sha256).digest()
    expected = "v1=" + base64.b64encode(digest).decode()
    return hmac.compare_digest(expected, signature)
```

</CodeGroup>

The SDKs provide the same check: `verifyWebhookSignature` and `constructWebhookEvent` in TypeScript, `VerifyWebhookSignature` and `ConstructWebhookEvent` in Go.

## Process each Job once

Deduplicate at two levels:

1. **Event:** store `Yir-Webhook-Id` and skip events you have already handled. Respond with a `2xx` status once the event is stored.
2. **Job:** polling and Webhooks can both report the same terminal Job. Key your business actions (saving files, charging or refunding your users) by `job.id` so they happen exactly once.

Read `billing.total_charged_by_yir` for the final charge. Result URLs in a delivery are short-lived and can differ between deliveries of the same event; download files promptly.

## Retries

If your endpoint does not answer with a `2xx` status, Yir retries automatically. Retries carry the same event ID with a new timestamp and signature. They never resubmit or charge the Job again. There is no manual redelivery.

If a callback is lost, `GET /v1/jobs/{id}` always returns the same terminal Job while it is retained. Many integrations treat the Webhook as a wake-up signal and keep slow polling as a fallback.

Do not log signatures, secrets, or result URLs.

## Endpoints and delivery history

[Console → Webhooks](https://yir.ai/console/webhooks) holds the account-wide endpoints, the signing secret, and delivery records.

| Endpoint setting | Rules |
| --- | --- |
| **URL** | A public HTTPS URL, up to 1000 characters. Each URL can be registered once. |
| **Description** | Optional, up to 200 characters. |
| **Enabled** | Only enabled endpoints receive deliveries. Disable an endpoint to pause it without deleting it. |

An endpoint receives every terminal Job event for your account, including Jobs submitted without `webhook_url`. You can register up to 5. Deleting one stops new deliveries to it and keeps its existing records.

The signing secret can be revealed, copied, or rotated. Rotation takes effect immediately and the previous secret stops working, so update your receiver right after rotating.

Each endpoint shows its total deliveries, success rate, and latest delivery. **View Deliveries** lists recent deliveries with the event, the Job (linked to [Logs](/docs/console#logs)), the last HTTP status or error, and the attempt count:

| Status | Meaning |
| --- | --- |
| Delivered | Your endpoint answered with a `2xx` status. |
| Retrying | The delivery failed and Yir will retry it automatically; the next retry time is shown. |
| Failed | Retries are exhausted, or the address was rejected (for example, not a public HTTPS host) and is not retried. |

Deliveries to a request-level `webhook_url` appear in that Job's detail in Logs. When the latest delivery to an endpoint fails, [Alerts](/docs/console#alerts) shows a warning.
