---
title: Authentication
description: Authenticate every Yir Gateway request with a Yir API Key in a Bearer header.
---

Every Gateway request uses a Yir API Key in the standard HTTP Bearer header:

```http
Authorization: Bearer <YIR_API_KEY>
```

`X-API-Key` and query-string keys are not accepted. Requests without a valid key fail with `401 YIR_UNAUTHORIZED` before any Job is created.

## Get your key

Every account has a **default API Key**, so you can start immediately. Open [Console → API Keys](https://yir.ai/console/api-keys) to reveal and copy it.

Store the key in a secret manager or server environment variable:

```bash
export YIR_API_KEY="your-yir-api-key"
```

Create additional keys when you want separate environments or applications, each with its own spend limit, expiry, IP allowlist, and usage statistics. See [API Keys in Console](/docs/console/api-keys).

## Keep keys safe

- Use keys only in server-side code. Never put them in browser or mobile apps, public repositories, URLs, screenshots, or support tickets.
- Use a separate key for production, CI, and local development so you can rotate or revoke each one independently.
- Rotate a key immediately if it may have been exposed. The old secret stops working as soon as rotation succeeds.
- Do not send provider API Keys (for example OpenAI or Google keys) to Yir. Yir uses its own managed provider accounts and never accepts upstream credentials from requests.

## Why a request can be rejected

A key is rejected with `401 YIR_UNAUTHORIZED` when it is wrong, rotated, revoked, expired, or used from an address outside its IP allowlist. The response does not reveal which reason applies. Check the key's status in Console.

A valid key can still be refused when creating a Job: `403 YIR_SPEND_LIMIT_EXCEEDED` means the key reached its monthly spend limit, and `402 YIR_INSUFFICIENT_BALANCE` means the account needs funds. See [error codes](/docs/support/error-codes).
