title: Quickstart
description: Generate your first image with the Yir Standard API, follow its Job, and download the result.
---

This walkthrough generates one image with GPT Image 2 using cURL. It takes three requests: submit, check status, download.

## Before you begin

- A Yir account with funds added in [Console](https://yir.ai/console/billing).
- Your API key from [Console → API Keys](https://yir.ai/console/api-keys). See [authentication](/docs/getting-started/authentication).
- A terminal with `curl` and `jq`.

```bash
export YIR_API_KEY="your-yir-api-key"
```

Keep the key on your server. Never ship it in browser or mobile code.

## 1. Submit a generation

Every generation needs an `Idempotency-Key`. Create one and keep it for this request:

```bash
export YIR_IDEMPOTENCY_KEY="quickstart-$(date +%s)"
```

```bash
curl https://gateway.yir.ai/v1/images/generations \
  --header "Authorization: Bearer $YIR_API_KEY" \
  --header "Content-Type: application/json" \
  --header "Idempotency-Key: $YIR_IDEMPOTENCY_KEY" \
  --data '{
    "model": "openai/gpt-image-2",
    "input": { "type": "text", "prompt": "A quiet observatory above a sea of clouds" },
    "parameters": { "resolution": "1K", "aspect_ratio": "1:1", "n": 1 }
  }' | tee job.json
```

Yir responds with HTTP `202` and a Job:

```json
{
  "id": "1234567890",
  "object": "job",
  "status": "queued",
  "model": "openai/gpt-image-2",
  "error": null,
  "created_at": 1790000000,
  "urls": { "get": "/v1/jobs/1234567890", "cancel": "/v1/jobs/1234567890/cancel" }
}
```

Save the `id`. It is the only handle you need from now on.

```bash
export YIR_JOB_ID="$(jq -r '.id' job.json)"
```

:::info
The key makes the submission safe to retry. If the request times out, run the same command again in the same shell: the same key and body return the original Job instead of creating a second one. A new key would create a new, separately charged Job. Requests without a key are rejected with `400 YIR_INVALID_REQUEST`. See [idempotent submission](/docs/guides/production-integration#idempotent-submission).
:::

## 2. Wait for the Job to finish

Query the lightweight status endpoint until the Job reaches a terminal state:

```bash
while true; do
  status="$(curl --silent https://gateway.yir.ai/v1/jobs/$YIR_JOB_ID/status \
    --header "Authorization: Bearer $YIR_API_KEY" | jq -r '.status')"
  echo "status: $status"
  case "$status" in
    succeeded|failed|cancelled) break ;;
    *) sleep 5 ;;
  esac
done
```

A Job moves through `queued` → `running` → `delivering` → `succeeded`. Image Jobs usually finish in tens of seconds; videos can take several minutes. See [Job lifecycle](/docs/concepts/task-lifecycle).

## 3. Download the result

Fetch the complete Job and download the file:

```bash
curl --silent https://gateway.yir.ai/v1/jobs/$YIR_JOB_ID \
  --header "Authorization: Bearer $YIR_API_KEY" > job.json

jq '{status, error, charged: .billing.total_charged_by_yir, file: .result.files[0]}' job.json

curl --location --output image.png "$(jq -r '.result.files[0].url' job.json)"
```

The result URL is a short-lived signed link: do not send your API key to it. Copy the file to your own storage. Results are kept for 7 days after the Job is created (see [results and retention](/docs/concepts/task-lifecycle#results-and-retention)).

If the Job `failed`, read `error.code` and `error.action` and look it up in [error codes](/docs/support/error-codes). Failed Jobs are not charged.

## Next steps

- **Check the price first.** Call `POST /v1/images/quotes` with the same body to see the price and spending ceiling before you submit. See [quotes and billing](/docs/concepts/billing).
- **Use an SDK.** The [TypeScript and Go SDKs](/docs/guides/clients) handle polling back-off, errors, and file uploads.
- **Go to production.** Follow the [production checklist](/docs/guides/production-integration).
