---
title: OpenAI compatibility and new-api
description: Call Yir with the OpenAI Images and Sora Videos protocols; new-api needs only one OpenAI channel.
---

Yir serves OpenAI Images and Sora `/v1/videos` compatible endpoints at `https://gateway.yir.ai/openai`. Systems already built on the OpenAI protocol only need a new Base URL and key. In new-api (verified on v0.13.x and the v1.0 RC), add one channel of type OpenAI; no plugin or code change is needed.

The compatible endpoints call the Standard API internally, so Jobs, routing, and billing work as described elsewhere in these docs. Use the Standard API directly when you need asynchronous submission, webhooks, or full routing control.

## new-api channel settings

| Setting | Value |
|---|---|
| Channel type | OpenAI |
| Base URL | `https://gateway.yir.ai/openai` |
| Key | A Yir API key (`yir_sk_…`) created on the Console API Keys page |
| Models | The Yir model IDs to expose; use **Fetch models** to load them |

- **Fetch models** lists only models with current supply, by canonical ID. Aliases still work in requests.
- **Update balance** returns the available balance (USD) of the account that owns the key.
- **Test** works with the default endpoint: Yir only checks the network, the key, and whether the model currently has supply. It generates nothing and charges nothing. Do not switch the test endpoint to image generation, which creates a real, billed image. Yir does not offer chat, so regular chat requests return 404.

When calling directly with an OpenAI SDK, set `base_url` to `https://gateway.yir.ai/openai/v1`.

## Model names

- Use Yir model IDs or aliases, for example `gpt-image-2` and `google/nano-banana-2` for images, `bytedance/seedance-1.5-pro` and `google/veo-3.1-fast-generate-001` for video. See [Models](/docs/guides/models) for the full list.
- **Use vendor-prefixed IDs for video models.** new-api's built-in Kling and Veo plugins take over models with matching names (such as `kling-*` and `veo-*`), so those requests would not reach the Yir channel.
- To show end users your own model names, map them to Yir model IDs with the channel's model redirect.

## Images

`POST /v1/images/generations` (JSON) and `POST /v1/images/edits` (multipart, `image` or `image[]`, up to 16 files).

| Parameter | Behavior |
|---|---|
| `size` | `WIDTHxHEIGHT`. Matched to the model's nearest resolution tier and aspect ratio (a model without 3:2 renders `1536x1024` as 4:3). Landscape never becomes portrait or the reverse; a model with no ratio in that orientation returns 400. Omitted or `auto` uses the model default |
| `quality` | `low` / `medium` / `high` (`hd` means `high`). Uses the model default when the model has no matching tier |
| `response_format` | `url` (default) or `b64_json`. Results over 12 MB fall back to `url` |
| `n` | Only 1 |
| `resolution`, `aspect_ratio` | Yir extensions that set the tier and ratio directly (such as `4K`, `21:9`) and take precedence over `size` |

The request waits for the image for up to 10 minutes and sends a newline every 10 seconds to keep the connection open. Success returns `{created, data: [{url} | {b64_json}]}`.

## Videos

`POST /v1/videos` (JSON or multipart), `GET /v1/videos/{id}`, and `GET /v1/videos/{id}/content`.

| Parameter | Behavior |
|---|---|
| `seconds` | Video length. Defaults to Sora's 4 seconds, or the model default when the model does not offer 4 seconds. Keep it consistent with your new-api pricing |
| `size` | `WIDTHxHEIGHT`. The short edge selects 480p / 720p / 1080p / 4K, and the aspect ratio is matched within the same orientation |
| `input_reference` | One multipart image used as the first frame |
| `resolution`, `aspect_ratio`, `generate_audio` | Yir extensions |

Submission returns an `id` (the Yir Job ID) immediately. new-api polls it and downloads the result from `/content`, which supports Range requests.

## Billing

- As with the Standard API, only successfully delivered results are charged; failures are free. See [Billing](/docs/concepts/billing).
- Price the channel in new-api at your own rates: per image, and per second for video. Yir model pages list the prices for each configuration.
- Set a monthly spend limit on the key in the Console to contain mistakes in configuration.

## Known limitations

- Result links are valid for 15 minutes; download them right away, or use `b64_json` to keep the bytes.
- An image that takes longer than the 10-minute wait returns a timeout error, but the Job continues and is charged if it succeeds. The same applies when the end client disconnects. Reconcile with the `X-Yir-Job-Id` response header.
- new-api's non-streaming relay sends nothing to the end client until the image is ready. For slow models, set the client timeout above 10 minutes, or use `stream: true` (the v1.0 RC relays it as a stream).
- `n > 1`, `mask`, and JSON image edits are not supported.
- Result links and response headers reveal Yir; use `b64_json` if that matters.

## Troubleshooting

| Response | Meaning |
|---|---|
| 400 `invalid_request_error` | The model does not support a parameter (size, seconds, quality, and so on); adjust it as the message says |
| 401 | The Yir key is invalid; new-api disables the channel |
| 402 `insufficient_quota` | Insufficient balance; new-api disables the channel. Re-enable it after topping up |
| 403 | The key's monthly limit is reached |
| 503 | No supply is available; new-api retries on another channel |
| 200 with `error` | The Job ran but failed (for example, blocked by content moderation); it is charged only what the channel billed, usually nothing |

Include the `X-Yir-Job-Id` response header when reporting a problem.
