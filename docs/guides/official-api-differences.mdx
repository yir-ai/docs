---
title: Differences from official APIs
description: How Yir's model parameters map to each provider's own API, which official options are not available, and the model-specific differences to know when migrating.
---

Yir exposes every model through one request shape so that a request can be quoted reliably and moved between channels. That means some parameters are named or structured differently from the model maker's own API, some official options are not available, and a few models accept only part of the official value range. This page lists those differences. When you migrate code written for a provider's API, check it against this page and the model's contract.

The model contract (`GET /v1/models/{creator}/{model}?view=contract`) is always the authoritative list of what Yir accepts. See [models and parameters](/docs/guides/models).

## Rules that apply to every model

| Topic | Official APIs | Yir |
| --- | --- | --- |
| Request shape | Each provider has its own endpoint and body. | One body for all models: `model`, `input` (prompt and references), `parameters`. See [image generation](/docs/guides/image-generation) and [video generation](/docs/guides/video-generation). |
| Execution | Often synchronous, sometimes streamed. | Always an asynchronous Job. Poll, long-poll or use a Webhook; there is no streaming or partial-image output. See [Job lifecycle](/docs/concepts/task-lifecycle). |
| Output size | Usually pixel sizes (`size`, `width`/`height`) or provider-specific presets. | `resolution` (a tier such as `1K`, `2K`, `4K`, or `480p`, `720p`, `1080p`) plus `aspect_ratio`. Yir translates them into each channel's native size, so exact pixel dimensions can differ by channel. |
| Number of outputs | Many APIs accept `n` greater than 1. | `n` is always `1`. Submit one Job per output, each with its own idempotency key. |
| Reference inputs | URLs, base64 data or multipart uploads, with provider-specific field names. | Upload through the [Files API](/docs/guides/input-files) and pass `file_id` with a role such as `reference_image`, `first_frame`, `last_frame`, `reference_video` or `reference_audio`. External URLs and inline data are rejected. |
| Unlisted parameters | Provider-specific options such as `seed`, `negative_prompt`, `style`, `output_format`, `background`, `moderation` or `user`. | Not accepted. `parameters` only takes the names in the model's contract; anything else fails with `400 YIR_INVALID_REQUEST`. Yir never forwards unknown fields to a channel. |
| Defaults | The provider's defaults, sometimes "let the model decide". | The `default` in Yir's contract. An omitted parameter means that default, which can differ from the provider's (see the model sections below). |
| Value ranges | Full official range. | Sometimes a subset of the official values, chosen so the request can be priced in advance and served by more than one channel. Explicit values are never silently rewritten: if no channel can serve a value, the quote reports `no_matching_supply` and a generation request is rejected. |
| Output files | Inline base64 or provider URLs, in the provider's format. | Files copied to Yir storage and returned as short-lived signed URLs in `result.files`. The file format is whatever the delivering channel produces. |
| Content moderation settings | Some APIs let you relax or tune moderation. | Not configurable. Yir checks inputs before creating a Job, and channels apply their own moderation. See [content safety](/docs/concepts/task-lifecycle#content-safety). |
| Credentials | Your own provider key. | Your Yir API key only. Yir does not accept or forward provider keys. |

## Model-specific differences

Differences that change what a request means, beyond the rules above. A model that is not listed here can still accept fewer values than its maker's API; its contract shows exactly what Yir accepts.

### GPT Image 2 and GPT Image 2.5

Models: `openai/gpt-image-2`, `openai/gpt-image-2.5-flare`, `openai/gpt-image-2.5-sunburst`.

| Parameter | OpenAI Images API | Yir |
| --- | --- | --- |
| `quality` | `auto` (default, the model picks the tier) or a fixed tier. | Only fixed tiers: `low`, `medium`, `high` for GPT Image 2, and also `xhigh`, `max` for GPT Image 2.5. `auto` is rejected because its cost cannot be quoted. A set tier is a minimum: only channels that serve it run the request. Omitted means any channel may run it, and channels with a quality setting use `medium`. |
| `size` | Pixel sizes such as `1024x1536`, custom `WIDTHxHEIGHT`, or `auto`. | Use `resolution` (`1K`, `2K`, `4K`) and `aspect_ratio` (including `auto`). |
| `n` | Several images per request. | Always `1`. |
| `background`, `output_format`, `output_compression` | Transparent backgrounds and PNG, JPEG or WebP output with compression. | Not available. |
| `moderation` | `auto` or `low`. | Not available. |
| `stream`, `partial_images` | Streamed partial images. | Not available; results arrive when the Job finishes. |
| `mask` | Inpainting mask on the edits endpoint. | Not available. Edits use `reference_image` references and the prompt. |

Migrating: replace `quality: "auto"` with a tier or omit it, and replace `size` with `resolution` plus `aspect_ratio`. See [GPT Image 2](/docs/models/gpt-image-2#differences-from-the-openai-api) and [GPT Image 2.5](/docs/models/gpt-image-2-5#differences-from-the-openai-api).

### Gemini Omni 1.1 Flash

Model: `google/gemini-omni-1.1-flash`.

| Parameter | Google API | Yir |
| --- | --- | --- |
| `duration` | Optional; Google's documentation describes lengths of about 3 to 10 seconds. | Only `4`, `6`, `8` or `10` seconds. Omitted means `4` seconds, a Yir default rather than Google's. There is no automatic length, because a fixed length is needed to quote the price. |

Migrating: set `duration` explicitly to one of the supported lengths; other values are rejected rather than rounded.
