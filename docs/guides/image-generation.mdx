---
title: Image generation
description: Generate images from text or reference images with the Yir Standard API.
---

Submit image Jobs to `POST /v1/images/generations`. The request shape is the same for every image model; each model's contract decides which parameter values and how many references it accepts.

## Request fields

| Field | Required | Description |
| --- | --- | --- |
| `model` | Yes | Model ID such as `openai/gpt-image-2`. See [models and parameters](/docs/guides/models). |
| `input` | Yes | `{ "type": "text", "prompt": ... }` or `{ "type": "image", "prompt": ..., "references": [...] }`. Prompts are 1–20,000 characters. |
| `parameters` | Yes | Model parameters, for example `resolution`, `aspect_ratio`, `quality`, and `n`. |
| `max_cost` | No | Spending limit for the whole Job in USD. See [billing](/docs/concepts/billing#set-a-spending-limit). |
| `routing` | No | Channel preference, allowlist, variants, and fallback. See [routing](/docs/concepts/routing). |
| `webhook_url` | No | HTTPS URL that receives the terminal Job. See [Webhooks](/docs/guides/webhooks). |

Each request produces one output (`n` is always `1`). To generate several images, submit several Jobs, each with its own idempotency key.

## Text to image

```json
{
  "model": "openai/gpt-image-2",
  "input": {
    "type": "text",
    "prompt": "A watercolor fox reading a map in a pine forest"
  },
  "parameters": { "resolution": "2K", "aspect_ratio": "3:2", "n": 1 }
}
```

## Image to image

Set `input.type` to `image` and list references in order. Every reference uses the role `reference_image` and exactly one of `url` (a public HTTPS URL) or `file_id` (an uploaded [input file](/docs/guides/input-files) in `ready` state).

```json
{
  "model": "openai/gpt-image-2",
  "input": {
    "type": "image",
    "prompt": "Put the product from the first image on the table in the second image",
    "references": [
      { "role": "reference_image", "url": "https://example.com/product.png" },
      { "role": "reference_image", "file_id": "file_11111111-1111-4111-8111-111111111111" }
    ]
  },
  "parameters": { "resolution": "1K", "aspect_ratio": "auto", "n": 1 }
}
```

Replace the example URL and file ID with your own. The model contract sets the maximum number of references; many models accept more than one.

## Model-specific parameters

Parameters are validated against the chosen model. Values that a model does not accept fail with `400 YIR_INVALID_REQUEST`. Some notable ones:

| Parameter | Models | Notes |
| --- | --- | --- |
| `quality` | GPT Image and others | GPT Image ignores it unless the request is pinned to the official channel. See [parameters that differ by channel](/docs/concepts/routing#parameters-that-differ-by-channel). |
| `web_search` | Nano Banana 2, Nano Banana Pro | Default `false`. Requires a channel that supports search; check the quote. |
| `image_search` | Nano Banana 2 | Requires `web_search: true`. |

Read the complete list for any model from `GET /v1/models/{creator}/{model}?view=contract`.

## Submit and collect

1. Optionally quote the request with `POST /v1/images/quotes` using the same body (without `max_cost` and `webhook_url`).
2. Submit to `POST /v1/images/generations` with the required `Idempotency-Key` header.
3. Poll `GET /v1/jobs/{id}/status`, or wait for a Webhook.
4. Read `GET /v1/jobs/{id}` and download `result.files[].url`. Each file carries `media_type` and, when known, `width` and `height`.

The [quickstart](/docs/getting-started/quickstart) shows every step with cURL.
