---
title: Vercel AI SDK
description: Use Yir as an image and video provider in the Vercel AI SDK through the official adapter.
---

The `@yir-ai/sdk/vercel` adapter lets `generateImage` and the experimental video functions of the [AI SDK](https://ai-sdk.dev) run on Yir. It sends the same Standard API requests as the native SDK, so Jobs, routing, and billing work exactly as described elsewhere in these docs.

The adapter targets AI SDK 7 (Provider V4) and is tested with `ai@7.0.97`. Use it on the server only.

```sh
pnpm add @yir-ai/sdk ai@7.0.97
```

## Images

```ts
import { generateImage } from "ai";
import { createYirAIProvider } from "@yir-ai/sdk/vercel";

const yir = createYirAIProvider(); // reads YIR_API_KEY

const { images } = await generateImage({
  model: yir.imageModel("openai/gpt-image-2"),
  prompt: "A quiet observatory above a sea of clouds",
  aspectRatio: "1:1",
  maxRetries: 0,
  providerOptions: {
    yir: {
      idempotencyKey: "order-123-image-1",
      maxCost: "0.05",
      parameters: { resolution: "1K" },
    },
  },
});
```

The image path submits the Job, waits for it, and downloads the result.

## Videos

For long video Jobs, start the Job and store the returned operation, then check it later, even from another process:

```ts
import { experimental_startVideo as startVideo, experimental_getVideoStatus as getVideoStatus } from "ai";

const model = yir.videoModel("bytedance/seedance-2.0");

const { operation } = await startVideo({
  model,
  prompt: "A paper boat drifting down a rain-covered street",
  maxRetries: 0,
  providerOptions: { yir: { idempotencyKey: "order-123-video-1", maxCost: "0.60" } },
});
// operation is { jobId, modelId } and is JSON-serializable: persist it.

const status = await getVideoStatus(model, { operation, maxRetries: 0 });
// status.status is "pending", "completed", or "error"
```

`experimental_generateVideo` is also supported and waits until the video is ready.

## Provider options

Pass Yir-specific options in `providerOptions.yir`. Unknown keys are rejected.

| Option | Description |
| --- | --- |
| `idempotencyKey` | Recommended for recovery across calls. Overrides `headers["Idempotency-Key"]`; otherwise the supplied header or a generated key is used. |
| `maxCost` | Optional cap on the Job's charge, as a decimal string. See [billing](/docs/concepts/billing#set-a-spending-limit). |
| `parameters` | Yir model parameters, such as `resolution`, `quality`, or `web_search`. |
| `routing` | Yir [routing](/docs/concepts/routing) object. `routing.only` is an unordered allowlist. |

## How AI SDK fields map

| AI SDK field | Yir request |
| --- | --- |
| Image `size`, video `resolution` | `parameters.size`, exact pixels without approximation |
| `aspectRatio` | `parameters.aspect_ratio` |
| `n` | `parameters.n` (must be `1`) |
| Video `duration`, `generateAudio` | `parameters.duration`, `parameters.generate_audio` |
| `webhookUrl` (video) | `webhook_url` |
| Prompt images, `frameImages` | Image references, first and last frame roles |
| `inputReferences` | Image, video, or audio references, chosen by the explicit MIME type |
| Inline bytes | Uploaded through the Files API first, then referenced by file ID |

Media inputs may be bytes (`Uint8Array`), Base64 data, or public HTTPS URLs. Bytes are uploaded through Files; URLs are passed to the Gateway without a local download. Private URLs, credentials in URLs, masks, and arbitrary per-call headers are rejected. Conflicting AI SDK fields and Yir parameters are rejected.

Exact pixels require a Gateway deployment with `parameters.size` support. The first declared scope is Seedream 5.0 Pro official image sizes (for example `1024x1024` or `3136x1344`). The Gateway derives omitted resolution tiers and aspect ratios from that declaration and rejects conflicting explicit values. Video has no declared exact-size channel yet and is rejected. Omitting size preserves existing defaults; a resolution tier alone does not guarantee exact pixels.

`seed` and video `fps` reach the Gateway as same-named parameters; acceptance depends on the current model/channel contract. `image()` / `video()` alias `imageModel()` / `videoModel()`. Image file-input capability is reported when a local model catalog is supplied; mask support is false.

The adapter accepts `Idempotency-Key` on both image and video calls, including video polling. `providerOptions.yir.idempotencyKey` takes precedence. AI SDK's video retry key is reused for submission and inline uploads; otherwise a key is generated. Persist a business key when recovering across separate calls or processes.

Optional video `fps` requires a Gateway deployment with FPS support. Initially only the official Google route for `google/veo-3.1-generate-001` declares native `24` FPS. Unsupported values or channels are rejected without interpolation or transcoding; omitting FPS preserves existing behavior.

`generateVideo({ webhook })` supports the standard callback factory. Its URL maps to `webhook_url`; after your verified, correlated terminal notification resolves `received`, the adapter reads the original Job for its result. It does not trust the notification body as the generated output. Without this option, polling is unchanged.

First-frame video input may omit prompt text only when the model input contract declares `prompt_optional` and a matching channel is available. Initially this is official Google Veo 3.1. Text-only generation, image generation, and other input modes still require text. Omitted or blank text is treated as absent; no prompt is invented. This requires the corresponding Gateway update.

## Things to keep in mind

- The adapter does not quote or approve budgets. Call `quoteImage` / `quoteVideo` on the [native client](/docs/integrations/sdk) first if you need prices.
- Set `maxRetries: 0`, or always pass a persisted `idempotencyKey`, so AI SDK retries cannot create extra Jobs.
- Aborting or timing out stops local waiting only. To stop the remote Job, call the native `cancelJob`; the current attempt may still succeed and be charged.
- Final `parameter_notices` and result warnings are returned as generation `warnings`. Auxiliary images, such as a last-frame image, are preserved in `providerMetadata.yir.additionalFiles`; only video files become generated videos. The Job ID and charge are in `providerMetadata.yir`.
