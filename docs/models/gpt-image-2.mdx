`openai/gpt-image-2` (alias `gpt-image-2`) is OpenAI's image generation and editing model. It supports text-to-image and image editing with reference images through the standard [image generation](/docs/guides/image-generation) endpoint.

## Example

```json
{
  "model": "openai/gpt-image-2",
  "input": {
    "type": "text",
    "prompt": "A watercolor fox reading a map in a pine forest"
  },
  "parameters": { "resolution": "2K", "aspect_ratio": "3:2", "n": 1 }
}
```

For image editing, set `input.type` to `image` and add `reference_image` references from the [Files API](/docs/guides/input-files).

## Parameters

| Parameter | Values | Default |
| --- | --- | --- |
| `resolution` | `1K`, `2K`, `4K` | `1K` |
| `aspect_ratio` | `auto`, `1:1`, `3:2`, `2:3`, `4:3`, `3:4`, `5:4`, `4:5`, `16:9`, `9:16`, `2:1`, `1:2`, `3:1`, `1:3`, `21:9`, `9:21` | `auto` |
| `quality` | `low`, `medium`, `high` | Not set. See [quality](#quality) |
| `n` | `1` | `1` |

The authoritative list, including reference limits, comes from `GET /v1/models/openai/gpt-image-2?view=contract`. Channels may support only some combinations, so [quote](/docs/concepts/billing#get-a-quote) the complete request.

## Quality

`quality` is the minimum quality tier you need. Yir treats it as a routing constraint: it is never ignored or lowered.

- **Omitted:** every channel may run the request. Channels with a quality setting generate at `medium`, and quotes estimate at `medium`.
- **Set:** only channels that serve that tier take part in routing and fallback. If none can, the quote reports `no_matching_supply` and a generation request is rejected.
- **`auto` is not accepted.** It lets the provider pick the tier, so the cost cannot be quoted reliably. Omit `quality` instead.

| Channel | Tiers served |
| --- | --- |
| Official (`openai`) | `medium`, `high` |
| APIMart `official` version | `medium`, `high` |
| APIMart standard version, KIE | `low`, `medium` |

APIMart's standard version and KIE have no quality setting. They render at a fixed quality of at least `medium`, so they serve `low` and `medium` requests at their per-image price. A `high` request runs only on the official channel or APIMart's `official` version.

```json
{
  "model": "openai/gpt-image-2",
  "input": { "type": "text", "prompt": "A product photo of a ceramic mug" },
  "parameters": { "resolution": "1K", "aspect_ratio": "1:1", "quality": "high", "n": 1 }
}
```

Model detail (`GET /v1/models/openai/gpt-image-2`) lists the tiers each channel serves in `channel_parameters[].parameter_rules.quality.values`. In [Model Market](https://yir.ai/models), choosing a quality tier marks the channels that do not serve it.

Jobs admitted under the earlier policy may still carry a `quality_requires_official_channel` notice in `parameter_notices`. New Jobs do not.

## Differences from the OpenAI API

Requests use Yir's [common request shape](/docs/guides/official-api-differences), so code written for the OpenAI Images API needs these changes:

| OpenAI | Yir |
| --- | --- |
| `quality: "auto"` (OpenAI's default) | Not accepted. Use `low`, `medium` or `high`, or omit `quality`. See [quality](#quality). |
| `size` (pixel sizes or `auto`) | `resolution` plus `aspect_ratio`. |
| `n` greater than 1 | `n` is always `1`; submit one Job per image. |
| `background`, `output_format`, `output_compression`, `moderation` | Not available. |
| `stream`, `partial_images` | Not available; the result arrives when the Job finishes. |
| `mask` for inpainting | Not available; edit with `reference_image` references and the prompt. |
| Image URLs or base64 inputs | Pass a public HTTPS `url`, or upload with the [Files API](/docs/guides/input-files) and pass `file_id`. Base64 is not accepted. |

## Billing

- Channels billed by tokens (official and APIMart's `official` version) return an output-only estimate: the price `kind` is `estimate` and `estimate.scope` is `output_only`. The estimate uses the requested tier, or `medium` when `quality` is omitted.
- Reference images on token-billed channels are billed separately as image input tokens. OpenAI counts input image tokens roughly by 32×32-pixel patches, with a per-image cap; the estimate does not include them.
- Channels with a fixed per-image price return `kind: fixed`; the tier does not change that price.
- The final charge is the sum of every channel-billed attempt's actual upstream cost × your discount, usually just the delivering attempt. See [quotes and billing](/docs/concepts/billing).
