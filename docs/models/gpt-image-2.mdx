`openai/gpt-image-2` (alias `gpt-image-2`) is OpenAI's image generation and editing model. It supports text-to-image and image editing with reference images through the standard [image generation](/docs/guides/image-generation) endpoint.

## Example

```json
{
  "model": "openai/gpt-image-2",
  "input": {
    "type": "text",
    "prompt": "A watercolor fox reading a map in a pine forest"
  },
  "parameters": { "resolution": "2K", "aspect_ratio": "3:2", "n": 1 }
}
```

For image editing, set `input.type` to `image` and add `reference_image` references from the [Files API](/docs/guides/input-files).

## Parameters

| Parameter | Values | Default |
| --- | --- | --- |
| `resolution` | `1K`, `2K`, `4K` | `1K` |
| `aspect_ratio` | `auto`, `1:1`, `3:2`, `2:3`, `4:3`, `3:4`, `5:4`, `4:5`, `16:9`, `9:16`, `2:1`, `1:2`, `3:1`, `1:3`, `21:9`, `9:21` | `auto` |
| `quality` | `auto`, `low`, `medium`, `high` | Not set. See [quality](#quality) |
| `n` | `1` | `1` |

The authoritative list, including reference limits, comes from `GET /v1/models/openai/gpt-image-2?view=contract`. Channels may support only some combinations, so [quote](/docs/concepts/billing#get-a-quote) the complete request.

## Quality

By default Yir **ignores** `quality` for GPT Image models, because most channels cannot control it. The notice reason is `quality_requires_official_channel`.

Yir keeps `quality` only when every channel your routing allows supports it:

| Routing | `quality` |
| --- | --- |
| No `routing`, or an allowlist that includes a channel without quality control | Ignored |
| `"only": ["openai"]` (or `["official"]`) | Kept |
| `"only": ["apimart"]` with `"variants": { "apimart": "official" }` | Kept |
| `"only": ["openai", "apimart"]` with `"variants": { "apimart": "official" }` | Kept |

```json
{
  "model": "openai/gpt-image-2",
  "input": { "type": "text", "prompt": "A product photo of a ceramic mug" },
  "parameters": { "resolution": "1K", "aspect_ratio": "1:1", "quality": "high", "n": 1 },
  "routing": { "only": ["apimart"], "variants": { "apimart": "official" } }
}
```

When quality is kept, these channels currently accept `medium` and `high`. A request for `auto` or `low` with such routing cannot be served by them, so check the quote's `supply` first.

When quality is ignored, or you omit it, channels that support quality receive `medium`, which matches the price estimate. Other channels use their own default.

### Where you see the notice

Ignored parameters are reported at each stage, never hidden:

1. **Model contract.** The `quality` parameter in `GET /v1/models/openai/gpt-image-2?view=contract` carries a `policy` with `only_provider: "openai"` and the reason. Model detail lists per-channel rules in `channel_parameters`. This tells you what *may* happen.
2. **Quote.** `parameter_notices` shows what is *expected* on the first channel for your routing, and `parameter_handling_may_vary: true` means a fallback channel may behave differently.
3. **Job.** A successful Job and its Webhook carry the `parameter_notices` of the attempt that delivered the result. This is what *actually* happened.

```json
{
  "parameter_notices": [
    {
      "name": "quality",
      "disposition": "ignored",
      "reason": "quality_requires_official_channel",
      "message": "GPT Image quality is ignored unless routing.only is [\"openai\"]."
    }
  ]
}
```

A channel that never sends quality upstream may instead report `channel_parameter_unsupported`. Keep the original `quality` in your request either way: changing it changes the request's idempotency identity, while the notice already tells you how it was applied.

## Billing

- Channels billed by tokens return an output-only estimate: the price `kind` is `estimate` and `estimate.scope` is `output_only`. The estimate uses the effective quality: `medium` when quality is ignored or omitted, otherwise the tier you set.
- Reference images on token-billed channels are billed separately as image input tokens. OpenAI counts input image tokens roughly by 32×32-pixel patches, with a per-image cap; the estimate does not include them.
- Channels with a fixed per-image price return `kind: fixed`.
- The final charge is the delivering channel's actual upstream cost × your discount. See [quotes and billing](/docs/concepts/billing).
