---
title: Differences from official APIs
description: How Yir's model parameters map to each provider's own API, which official options are unavailable, and what differs per model when migrating.
---

Yir exposes every model through one request shape so that a request can be quoted reliably and moved between channels. That means some parameters are named or structured differently from the model maker's own API, some official options are not available, and a few models accept only part of the official value range. This page lists those differences. When you migrate code written for a provider's API, check it against this page and the model's contract.

The model contract (`GET /v1/models/{creator}/{model}?view=contract`) is always the authoritative list of what Yir accepts. See [models and parameters](/docs/models).

## Rules that apply to every model

| Topic | Official APIs | Yir |
| --- | --- | --- |
| Request shape | Each provider has its own endpoint and body. | One body for all models: `model`, `input` (prompt and references), `parameters`. See [image generation](/docs/guides/image-generation), [video generation](/docs/guides/video-generation), [music generation](/docs/guides/music-generation) and [3D generation](/docs/guides/3d-generation). |
| Execution | Often synchronous, sometimes streamed. | Always an asynchronous Job. Poll, long-poll or use a Webhook; there is no streaming or partial-image output. See [Job lifecycle](/docs/concepts/task-lifecycle). |
| Output size | Usually pixel sizes (`size`, `width`/`height`) or provider-specific presets. | `resolution` (a tier such as `1K`, `2K`, `4K`, or `480p`, `720p`, `1080p`) plus `aspect_ratio`. Yir translates them into each channel's native size, so exact pixel dimensions can differ by channel. |
| Number of outputs | Many APIs accept `n` greater than 1. | `n` is `1`, except the Suno v6 models (`suno/suno-v6`, `suno/suno-v6-wild`, `suno/suno-v6-mini`), which always make two tracks (`n: 2`). Submit one Job per output, each with its own idempotency key. |
| Reference inputs | URLs, base64 data or multipart uploads, with provider-specific field names. | A `file_id` from the [Files API](/docs/guides/input-files) or a public HTTPS `url`, with a role such as `reference_image`, `first_frame`, `last_frame`, `reference_video`, `reference_audio`, or `front_view`, `left_view`, `back_view` and `right_view` for 3D multi-view input. Base64, data URLs and multipart bodies are rejected. |
| Unlisted parameters | Provider-specific options such as `seed`, `negative_prompt`, `style`, `output_format`, `background`, `moderation` or `user`. | Not accepted. `parameters` only takes the names in the model's contract; anything else fails with `400 YIR_INVALID_REQUEST`. Yir never forwards unknown fields to a channel. |
| Defaults | The provider's defaults, sometimes "let the model decide". | The `default` in Yir's contract. An omitted parameter means that default, which can differ from the provider's (see the model sections below). |
| Value ranges | Full official range. | Sometimes a subset of the official values, chosen so the request can be priced in advance and served by more than one channel. Explicit values are never silently rewritten: if no channel can serve a value, the quote reports `no_matching_supply` and a generation request is rejected. |
| Output files | Inline base64 or provider URLs, in the provider's format. | Files copied to Yir storage and returned as short-lived signed URLs in `result.files`. The file format is whatever the delivering channel produces. |
| Content moderation settings | Some APIs let you relax or tune moderation. | Not configurable. Channels apply their own moderation; Yir checks reference images before submission and image output from channels without moderation. See [content safety](/docs/concepts/task-lifecycle#content-safety). |
| Credentials | Your own provider key. | Your Yir API Key only. Yir does not accept or forward provider keys. |

## Model-specific differences

Differences that change what a request means, beyond the rules above, checked against each maker's own API documentation (2026-10-04). Only differences that matter when migrating are listed; parameters already covered by the rules above, such as `seed`, `negative_prompt` or `watermark`, are not repeated per model. Reve's full API reference requires a Reve account, so Reve 2.1 is checked against Reve's official Python SDK (`reve` on PyPI, 2026-10-05). The model contract is always the exact list of what Yir accepts.

### GPT Image 2 and GPT Image 2.5

Models: `openai/gpt-image-2`, `openai/gpt-image-2.5-flare`, `openai/gpt-image-2.5-sunburst`.

| Parameter | OpenAI Images API | Yir |
| --- | --- | --- |
| `quality` | `auto` (default, the model picks the tier) or a fixed tier. | Only fixed tiers: `low`, `medium`, `high` for GPT Image 2, and also `xhigh`, `max` for GPT Image 2.5. `auto` is rejected because its cost cannot be quoted. A set tier is a minimum: only channels that serve it run the request. Omitted means any channel may run it, and channels with a quality setting use `medium`. |
| `size` | Pixel sizes such as `1024x1536`, custom `WIDTHxHEIGHT`, or `auto`. | Use `resolution` (`1K`, `2K`, `4K`) and `aspect_ratio` (including `auto`). |
| `n` | Several images per request. | Always `1`. |
| `background`, `output_format`, `output_compression` | Transparent backgrounds and PNG, JPEG or WebP output with compression. | Not available. |
| `moderation` | `auto` or `low`. | Not available. |
| `stream`, `partial_images` | Streamed partial images. | Not available; results arrive when the Job finishes. |
| `mask` | Inpainting mask on the edits endpoint. | Not available. Edits use `reference_image` references and the prompt. |

Migrating: replace `quality: "auto"` with a tier or omit it, and replace `size` with `resolution` plus `aspect_ratio`. See [GPT Image 2](/docs/models/openai/gpt-image-2#differences-from-the-openai-api) and [GPT Image 2.5](/docs/models/openai/gpt-image-2-5-flare#differences-from-the-openai-api).

### Gemini Omni 1.1 Flash

Model: `google/gemini-omni-1.1-flash`.

| Parameter | Google API | Yir |
| --- | --- | --- |
| `duration` | Optional; Google's documentation describes lengths of about 3 to 10 seconds. | Only `4`, `6`, `8` or `10` seconds. Omitted means `4` seconds, a Yir default rather than Google's. There is no automatic length, because a fixed length is needed to quote the price. |
| `resolution` | `360p`, `720p`, `1080p`, `4k`. | `720p`, `1080p`, `4K`. No `360p`. |
| Last frame | First-to-last-frame interpolation. | `image` mode accepts a `first_frame` plus an optional `last_frame`. First and last frames run on the KIE channel only. |
| Reference images | Several reference images. | Up to 7 `reference_image` references; more than 3 runs on the KIE channel only. |
| Reference videos, edit, extend | Supported. | Not available. |

Migrating: set `duration` explicitly to one of the supported lengths; other values are rejected rather than rounded.

### ByteDance Seedance and Seedream

Yir's Seedance defaults differ from ByteDance's: when omitted, `resolution` is `480p` (`720p` for Seedance 2.5) instead of `720p`, `duration` is `4` seconds (`5` for 2.0 Fast and 2.0 Mini) instead of `5` or model-chosen, `aspect_ratio` is `16:9` instead of `adaptive` (Seedance 2.5 with a first frame uses `auto`), and `generate_audio` is `false` instead of `true`. Set these parameters explicitly if you relied on ByteDance's defaults. The upstream `duration: -1` value is not accepted directly. Seedance 2.5 reference-video edits can use Yir's `duration: "auto"` with `aspect_ratio: "auto"`; other input modes retain fixed durations. `camera_fixed`, `draft`, `service_tier` and `priority` are not available on any Seedance model.

| Model | Parameter or feature | ByteDance API | Yir |
| --- | --- | --- | --- |

| `bytedance/seedance-2.0` | `resolution` | Up to `4k`. | Up to `4K`; `4K` runs on the APIMart standard and KIE channels only. |
| `bytedance/seedance-2.0-fast`, `-2.0-mini` | `aspect_ratio` | Includes `adaptive`. | Fixed ratios only. |
| `bytedance/seedance-2.5` | `resolution` | Up to `1080p`. | `480p`, `720p` or `1080p` for text, image and reference input. Default remains `720p`. |
| `bytedance/seedance-2.5` | `aspect_ratio` | `adaptive`, the only option with a first frame or first and last frames. | Named `auto`. With a first frame or first and last frames, only `auto` is accepted and it is the default. |
| `bytedance/seedance-2.5` | Video editing (`omni_reference_task_type`), audio-only references, `output_format: mov` | Available. | No explicit task-type or MOV parameter. Video edits can use `duration: "auto"` with a reference video and `aspect_ratio: "auto"`. Audio-only references (up to 10 `reference_audio` clips) run on the APIMart channel only. |
| `bytedance/seedream-4.5` | References | Up to 14 images. | Up to 10. `9:21` only with references. |
| `bytedance/seedream-4.5`, `-5.0`, `-5.0-pro` | Image sets (`sequential_image_generation`, `max_images`) | Up to 15 images per request. | One image per Job. |

| `bytedance/seedream-5.0-pro` | Layer decomposition, transparent background, prompt optimization mode | Available. | Not available. |
