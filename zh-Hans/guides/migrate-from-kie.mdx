---
title: "从 KIE 迁移"
description: "保留 KIE-compatible 请求结构，只修改 base URL。"
---

YIR 的 KIE-compatible 路由用于最小迁移。

## 迁移前

```bash
curl https://api.kie.ai/api/v1/jobs/createTask \
  -H "Authorization: Bearer <upstream_kie_key>" \
  -H "Content-Type: application/json" \
  -d @request.json
```

## 迁移后

```bash
curl https://api.yir.ai/x-router/kie/api/v1/jobs/createTask \
  -H "X-YIR-API-Key: yir_sk_..." \
  -H "Authorization: Bearer <upstream_kie_key>" \
  -H "Content-Type: application/json" \
  -d @request.json
```

保留请求体和原上游 `Authorization` Header。新增 `X-YIR-API-Key`，然后修改 base URL，并给 path 加 `/x-router/kie` 前缀。

## 查询状态

```bash
curl "https://api.yir.ai/x-router/kie/api/v1/jobs/recordInfo?taskId=93020" \
  -H "X-YIR-API-Key: yir_sk_..." \
  -H "Authorization: Bearer <upstream_kie_key>"
```

如果 task 由 YIR 创建，YIR 会返回从托管任务状态映射出来的 KIE-compatible 状态。如果是上游原平台 task id，YIR 可在配置允许时透传查询到 KIE。
